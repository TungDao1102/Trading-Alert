# Live Telegram + Binance test, 2026-10-04

Operator-run probe of the real Telegram bot and the Binance Demo Trading account, driven through the project's own
adapters. Nothing was written to PostgreSQL or to mainnet. Scratch scripts were not committed; the recipes that matter
are inlined below.

## Environment verified

| Item | Result |
|------|--------|
| Telegram bot | `@tungdao_bot`, token and authorized chat id present, no webhook, 0 pending updates |
| Binance Demo (`demo-fapi.binance.com`) | key from `BINANCE_TESTNET_*` valid **for trading**; one-way mode; 5000 USDT / 5000 USDC / 0.01 BTC; BTCUSDT tick 0.10, step 0.0001, min notional 50; taker 0.0004, maker 0.0002 |
| Binance mainnet | public endpoints through `BinanceUsdmAdapter` ok (920 symbols, klines, mark klines, OI, funding); real key is read-only (`BINANCE_LIVE_*` not yet set) |

| SDK | `BinanceUsdmAdapter(sdk_client)` works against demo when given `ConfigurationRestAPI(base_path=DERIVATIVES_TRADING_USDS_FUTURES_REST_API_DEMO_URL)` |

## What worked

- `notify_simulate` sent a SIMULATE message, `SENT` on the first attempt, 12 fields present.
- Real `build_application` + `dispatch_callback` (in-memory stores): SKIP and APPROVE each moved PENDING to the decided state exactly once; 3 taps gave 1 `SAVE` and 2 replays, all `ok=True`; CALLBACK_RECEIVED then CALLBACK_RESOLVED journaled per tap.
- Demo LIMIT place, query by client id, cancel; algo (STOP_MARKET, reduce-only, explicit quantity) place, query, cancel.
- With a filled position: `closePosition=true` SL (STOP_MARKET) and TP (TAKE_PROFIT_MARKET) accepted.
- Round trip of 0.001 BTC: open 84816.4, close 84799.9 (closed by the probe's own cleanup, **not** by SL/TP; both were 10% away), PnL -0.0165, fees 0.0339 + 0.0339, net about -0.084 USDT. Account left flat.
