# Lane X02: mutation_probe

## Scope

Technique lane: do the tests notice when safety code breaks? One small hand-made mutation per
safety behaviour, applied in the scratch clone `tmp/mutation_probe/clone` (clone of
`AUDIT/snapshot`, commit `55885b9`), then only the named test files are run
(`pytest -p no:cacheprovider -x -q`, no `-n`, `TEST_DATABASE_URL`/`DATABASE_URL` unset, no
`BINANCE_*`), then `git checkout -- .`. Harness: `tmp/mutation_probe/mut.py`; raw pytest tails:
`tmp/mutation_probe/logs/<id>.log`.

Limits that apply to every row: `*_pg.py` tests skip (no database), so a guard pinned only by a
PostgreSQL test shows as SURVIVED here and is marked `PG?` after a check of the `*_pg.py` files.
Only the test files named in the row ran; "SURVIVED" means "not killed by these files", and each
survivor that became a finding was re-checked with a grep of `tests/` for the guard.
