**Gathered:** 2026-09-26

## Phase Boundary

Phase 07.1 closes the binding hole between registry cost keys and backtest experiment identity: today `assemble()` in `src/backtest/experiment.py` accepts an independently-supplied `CostModel` and `simulator.run` builds it via `build_cost_model(case_input["cost_model"])` from a caller-supplied dict — nothing proves either equals the cost keys inside the registered `ParameterSet` whose `parameter_set_hash` enters the same identity. An experiment can therefore bind registry set A's strategy hash with cost dict B's `cost_model_hash` without detection. This phase adds a fail-closed binding gate so only registry-consistent cost models are assemblable. No simulator semantics changes (no fill/cost-formula touch), no report changes, no PG mirror, no WS/paper/Telegram/execution work. Success means a mismatched registry-set + cost-dict combination is unassemblable (raises), while every currently-consistent record still assembles byte-identically.

## Implementation Decisions

### Binding enforcement point

- **D-01:** Enforce inside `assemble()` — the single choke point where registry identity and cost identity meet. `assemble()` loads the `ParameterSet` from the registry (already does, fail-closed on `UnregisteredParameterSet`), builds the expected `CostModel` from the set's cost-key slice, and compares its canonical `cost_model_hash` against the caller-supplied `cost_model.cost_model_hash`; mismatch raises (D-03). `reproduce()` already binds hashes at replay time, so assembly is the only unguarded hole — no separate verifier module, and `simulator.run` stays registry-agnostic (it keeps accepting an explicit `CostModel`, preserving the backtest purity boundary). — **Reversibility:** costly — the gate sits on every experiment assembly path including baselines; removing it re-opens silent mismatch.
- [auto] Binding enforcement point — Q: "Enforce ở assemble() vs verifier rời vs simulator tự derive từ registry?" → Selected: "Enforce trong assemble()" (recommended default)

### Cost-key source of truth / dict dedup

- **D-02:** Keep both representations, add the binding check — do NOT delete the `cost_model` dicts from simulator inputs/fixtures. The registry TOML (`params/<family>/baseline-v*.toml` cost keys) is the authority; the dict is an explicit snapshot the gate verifies. Rationale: fixtures need self-contained cost snapshots for byte-exact replay without a registry checkout, and `simulator.run` must stay decoupled from `src/domain/registry.py`. A shared assertion helper (e.g. `assert_cost_model_binds_registry`-style, planner/researcher naming) is reused by `assemble()` and the new gate tests so the comparison logic exists exactly once. — **Reversibility:** costly — fixture shapes and the helper's call sites persist across phase6/phase7.1 suites.
- [auto] Cost-key source of truth — Q: "Giữ cost_model dict + binding check vs xóa dict, derive mọi nơi từ registry?" → Selected: "Giữ dict + binding check" (recommended default)

### Mismatch failure semantics

- **D-03:** Fail closed with a dedicated exception at assembly time (e.g. `CostModelBindingMismatch`-style; exact name at planner/researcher discretion — must NOT reuse `ExperimentReproducibilityBroken`, which means replay drift, not assembly refusal). Never a warning, never log-and-continue, never a NO_TRADE-style reason code: a mismatched binding is a programming/identity error, not a market outcome, and the project fail-closed posture (Phase-5 D-04 precedent) demands a loud raise before any record exists. — **Reversibility:** reversible — exception vocabulary grows additively.
- [auto] Mismatch failure semantics — Q: "Raise exception vs reason code vs warning?" → Selected: "Raise dedicated exception, fail-closed" (recommended default)

### Identity-hash treatment

- **D-04:** Keep the six-field identity tuple byte-stable — `experiment_id` derivation, `cost_model_hash` computation, and `ExperimentRecord` shape are untouched. Published experiment IDs/hashes are permanent references (Phase-6 D-03, one-way); the fix only shrinks the set of assemblable inputs, it never changes what a consistent input hashes to. Every currently-consistent record must still assemble to the identical `experiment_id` after the change (regression pinned by fixture). — **Reversibility:** one-way — anything that alters published IDs would invalidate prior evidence; this decision explicitly forbids that.
- [auto] Identity-hash treatment — Q: "Giữ nguyên six-field tuple vs gộp/derive lại hash?" → Selected: "Giữ nguyên six-field, chỉ siết input" (recommended default)

### Fixture + migration scope + spelling-sensitivity rule

- **D-05:** New `tests/fixtures/phase7.1/` binding fixtures (match case assembles byte-identically; mismatch cases raise the D-03 exception — cover at minimum: wrong fee rate, wrong `funding_treatment` string, `partial_fill_fraction` spelling/precision drift) plus a binding gate test module; existing `tests/fixtures/phase6/` files are NOT regenerated. Comparison is canonical-hash-to-hash (`build_cost_model(registry_slice).cost_model_hash == passed.cost_model_hash`), spelling-sensitive per Phase-3 D-04/D-12 trailing-precision precedent (`Decimal("0.00020")` ≠ `Decimal("0.0002")` at hash level) — so registry TOML and fixture dicts must carry identical spellings, and the researcher MUST audit every phase6 fixture's `cost_model` dict against its referenced registry TOML: latent mismatches are reported as findings (fix the fixture spelling or grandfather with a logged reason — never silently re-hash). — **Reversibility:** costly — new fixture dir and the audit verdict persist as the binding's evidence base.
