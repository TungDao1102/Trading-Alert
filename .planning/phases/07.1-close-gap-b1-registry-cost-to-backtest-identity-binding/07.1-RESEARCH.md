## Summary

The B1 hole is real and precisely bounded. `assemble()` in `src/backtest/experiment.py:169-234` loads the registry `ParameterSet` but consumes only `parameter_set.parameter_set_hash`; the caller-supplied `CostModel` enters the identity payload only via `cost_model.cost_model_hash` with no cross-check that the two came from the same cost assumptions [VERIFIED: src/backtest/experiment.py:196-218]. `simulator.run` builds its `CostModel` from a caller-supplied dict at `src/backtest/simulator.py:715` and checks only `strategy_version` against the registry (CR-10 precedent, lines 733-738) — never cost keys [VERIFIED: src/backtest/simulator.py:706-738]. `_check_inputs_bind_record` (experiment.py:310-343) binds replay *inputs* to the *record*, not the record to the *registry*, so it cannot catch a mismatched pair baked at assembly time [VERIFIED: src/backtest/experiment.py:310-343].

The fixture audit (executed against the real code this session) shows the hole is not hypothetical: **all 10 cost-carrying phase6 fixtures diverge from their referenced registry TOML at canonical-hash level**, in two distinct ways. Eight fixtures referencing `trend-pullback/baseline-v2` cannot bind at all — that TOML (and all three `baseline-v2.toml` files) carries only 3 of the 7 `COST_KEYS`, so `build_cost_model()` over the registry slice raises `KeyError` [VERIFIED: audit run 2026-09-26, see table]. The two baseline fixtures (`baseline-no-trade-v1`, `baseline-simple-trend-v1`) carry all 7 keys but still hash-mismatch on a single key: TOML `partial_fill_fraction = 1.0` normalizes to int `1` (whole-number rule) while fixtures spell `"1.0"` → `Decimal("1.0")`, and canonical JSON renders `"1"` vs `"1.0"` — different bytes, different `cost_model_hash` [VERIFIED: canonical bytes printed in-session].

**Primary recommendation:** Enforce the D-01 gate in `assemble()` as canonical-hash-to-hash comparison (`build_cost_model(registry_slice).cost_model_hash == passed.cost_model_hash`), raising a new dedicated exception; ship new `baseline-v3` registry TOMLs carrying all 7 cost keys (INSERT-only versioning — never edit `baseline-v2`, whose hashes are permanent per D-04); write phase7.1 match-case fixtures with whole-number cost spellings as JSON ints (`1`, not `"1.0"`); grandfather (do not regenerate) phase6 fixtures and migrate the experiment *tests* that call `assemble()` onto v3 sets.

### Pattern 2: Shared assertion helper, single comparison site (D-02)

**What:** One function owns the slice→build→compare logic; `assemble()` and the gate tests both call it. Comparison logic exists exactly once per D-02.

**When to use:** Always — the helper lives under the `src/backtest/` purity contract (stdlib + `Decimal` only), takes `(ParameterSet, CostModel)`, returns `None` or raises.

### Anti-Patterns to Avoid

- **Value-equality comparison (`Decimal(registry) == Decimal(passed)`):** passes `Decimal(1) == Decimal(1.0)` as equal, silently re-hashing distinct spellings into one identity — violates D-05 spelling-sensitivity. Always compare `cost_model_hash` strings.
- **Normalizing spellings before hashing ("helpful" `str(Decimal(v))` round-trip):** `costs._coerce_decimal` deliberately returns `Decimal` inputs AS-IS and documents why round-tripping through `str()` would drop trailing precision [VERIFIED: src/backtest/costs.py:38-58]. Never "fix" this.
- **Editing `baseline-v2` TOMLs to add missing keys:** changes `parameter_set_hash` → changes published `experiment_id`s → violates D-04 one-way permanence. New versioned files only.
- **Reusing `ExperimentReproducibilityBroken` for gate refusal:** that exception means *replay drift* on an existing record; the gate means *assembly refusal* before any record exists (D-03). Separate type required.
- **Catching `KeyError` from a key-absent registry slice and skipping the gate:** silently re-opens the hole for v1/v2 sets. Missing keys must raise (fail closed), never skip.

## Common Pitfalls

### Pitfall 1: TOML whole numbers can never carry trailing precision

**What goes wrong:** Planner writes `partial_fill_fraction = 1.0` in a new v3 TOML expecting `Decimal("1.0")`, then a fixture spelling `"1.0"` still mismatches — or worse, "fixes" it by string-typing the TOML value.
**Why it happens:** `_normalize_value` converts whole-number floats to int *before* consulting the raw string (`if value.is_integer(): return int(value)`) [VERIFIED: src/domain/registry.py:195-208]. Registry-side whole numbers are always int, always hash as `"1"`.
**How to avoid:** v3 TOMLs use fractional cost values where a Decimal identity matters, or accept int `1`; phase7.1 fixtures mirror with JSON int `1`. Never put a quoted numeric string in TOML for a `DECIMAL_KEYS` member — `_check_param_types` rejects non-`(int, Decimal)` for those keys [VERIFIED: src/domain/registry.py:300-305].
**Warning signs:** Any plan text saying "spell TOML as 1.0 to match fixture" — impossible by construction.

### Pitfall 2: Gate changes *which inputs assemble*, never *what they hash to* (D-04)

**What goes wrong:** Implementation "helpfully" includes the comparison result, the expected hash, or a binding flag in `identity_payload` or `ExperimentRecord`.
**Why it happens:** Natural instinct to record that the check ran.
**How to avoid:** Gate code sits strictly between `load_parameter_set()` and `_universe_hash()`/`identity_payload`; the payload dict (strategy_id, strategy_version, parameter_set_hash, data_snapshot_id, code_version, cost_model_hash, run_type, time range, universe_hash) [VERIFIED: src/backtest/experiment.py:206-217] and the `ExperimentRecord` field list [VERIFIED: src/backtest/experiment.py:108-120] are byte-identical before/after. Regression test: assemble a phase7.1 match case twice (pre/post gate code path) and assert identical `experiment_id`.
**Warning signs:** Diff touching lines 206-234 field lists, or `__all__`/dataclass field changes.

### Pitfall 3: `reproduce()` with a hand-forged record is a known residual, not this phase

**What goes wrong:** Scope creep — "while we're at it, verify registry binding in `_check_inputs_bind_record` too."
**Why it happens:** `_check_inputs_bind_record` rebuilds `build_cost_model(simulator_inputs["cost_model"])` and compares to the record hash [VERIFIED: src/backtest/experiment.py:336-338] — tempting to add a registry check there.
**How to avoid:** D-01 explicitly scopes to assembly ("`reproduce()` already binds hashes at replay time, so assembly is the only unguarded hole"). A hand-constructed `ExperimentRecord` with self-consistent-but-registry-divergent hashes is outside the threat model (records are built by `assemble()`). Note as residual, do not implement.

### Pitfall 4: Baseline tests call `simulator_run` directly — gate must not affect them

**What goes wrong:** Planner routes the gate through `simulator.run` or a shared input-parsing path, breaking `test_backtest_simulator.py` and the baseline tests that bypass `assemble()`.
**Why it happens:** `simulator.run` also calls `load_parameter_set` + `build_cost_model`, looking like a second enforcement point.
**How to avoid:** D-01 keeps `simulator.run` registry-agnostic for costs. Only `assemble()`, `baseline_no_trade`, and `baseline_simple_trend` (which delegate to `simulator_run` *after* their own param checks) are in play — and baselines need no gate change at all (they take caller dicts, not `CostModel` objects).

### Pitfall 5: New module must join three enforcement lists

**What goes wrong:** `binding.py` created but omitted from the AST no-float scan, mypy strict already covers `src/` (automatic), or Ruff line-length violated.
**Why it happens:** The scan list is an explicit tuple (`SCANNED_FILES`) that Phase 6 extended by hand [VERIFIED: tests/test_domain_no_float.py:17-51, ending with `src/backtest/report.py`].
**How to avoid:** Plan includes adding `"src/backtest/binding.py"` to `SCANNED_FILES`, running `ruff check` + `ruff format --check`, and `mypy` strict — all as explicit verification steps.

### Pitfall 6: Bare-interpreter test runs fail on missing third-party imports (environment, not code)

**What goes wrong:** Executor runs `python -m pytest` with system Python and sees `ModuleNotFoundError: No module named 'structlog'` from `src/risk/quantization.py:207`, concluding the phase broke risk code.
**Why it happens:** Verified this session: system interpreter is Python 3.14.3 while the project pins `==3.13.*` with `uv`-managed deps (`structlog>=25` in pyproject dependencies) [VERIFIED: pyproject.toml:1-7,26]. Two phase6 experiment tests (`test_baseline_simple_trend_returns_single_direction`, `test_cr03b_…`) fail on the bare interpreter for exactly this reason — pre-existing, unrelated to B1.
**How to avoid:** All test commands via `uv run --python 3.13 pytest …` (or the project's locked venv). Record the two failures as environment-caused baseline noise, not regressions.

## Code Examples

### Gate helper skeleton (purity-contract compliant)

```python
# Source pattern: in-repo — simulator.py:733-738 (CR-10 message shape),
# costs.py:137-157 (build_cost_model), registry cost slice via COST_KEYS.
"""Registry↔cost binding gate (Phase 7.1, D-01/D-02/D-03)."""
from __future__ import annotations

from src.domain.registry import ParameterSet

from .costs import COST_KEYS, CostModel, build_cost_model


class CostModelBindingMismatch(Exception):
    """Raised when a CostModel does not bind the registry ParameterSet."""


def assert_cost_model_binds_registry(
    parameter_set: ParameterSet, cost_model: CostModel
) -> None:
    """Return None iff cost_model equals the registry cost-key slice.

    Fail closed: absent slice keys raise KeyError (never silent defaults,
    mirroring build_cost_model); hash inequality raises
    CostModelBindingMismatch naming both hashes and the set identity.
    """
    registry_slice = {k: parameter_set.params[k] for k in COST_KEYS}
    expected = build_cost_model(registry_slice)
    if expected.cost_model_hash != cost_model.cost_model_hash:
        raise CostModelBindingMismatch(
            f"cost_model_hash {cost_model.cost_model_hash!r} != registry-derived "
            f"{expected.cost_model_hash!r} for "
            f"{parameter_set.strategy_id}/{parameter_set.parameter_set_id}"
        )
```
