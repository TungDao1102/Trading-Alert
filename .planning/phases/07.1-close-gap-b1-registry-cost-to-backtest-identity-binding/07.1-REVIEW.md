## Warnings

### WR-01: `assemble()` docstring omits the two new failure modes

**File:** `src/backtest/experiment.py:192-196`
**Issue:** The `Raises:` block still documents only
`UnregisteredParameterSet` and `IncompleteExperimentRecord`. Since 07.1-01,
`assemble()` can also raise `CostModelBindingMismatch` (present-but-unequal
cost slice) and bare `KeyError` (registry set predates the 7-key vocabulary,
e.g. every `baseline-v2` set). Any caller written against the documented
contract — e.g. catching only the two listed exceptions around a batch
assembly loop — will see an uncovered exception type escape. The new test
module proves both paths exist, so the docstring is now factually stale.
**Fix:** Extend the `Raises:` block:

```python
Raises:
    UnregisteredParameterSet: parameter_set_id not in registry.
    IncompleteExperimentRecord: any identity field missing or
        malformed.
    CostModelBindingMismatch: caller-supplied cost_model hash differs
        from the registry-derived slice (assembly refusal, D-03).
    KeyError: registry set lacks one of the seven COST_KEYS
        (pre-7-key sets such as baseline-v2; fail closed, never
        translated — D-02/D-05).
```

### WR-02: `build_cost_model` `str()` coercion defeats `CostModel` strict string validation

**File:** `src/backtest/costs.py:147,151-152` (pre-existing lines, newly load-bearing via the gate)
**Issue:** `build_cost_model` coerces the three string-valued cost keys with
`str(...)`, while `CostModel.__post_init__` strictly requires non-empty
`str` (lines 116-119). The coercion runs first, so a mistyped fixture value
such as `funding_treatment: None` or `123` is silently converted to
`"None"`/`"123"` and sails past the strict check that was designed to catch
exactly that. The failure then surfaces downstream as a hash mismatch
(`CostModelBindingMismatch`) rather than at the true fault (wrong type),
misdirecting debugging. The registry side cannot produce non-strings
(`_check_param_types` enforces `STRING_KEYS`), so this only masks
fixture/caller-side authoring errors — but fail-closed posture prefers the
loud type error at the boundary. Flagged because 07.1 promotes
`build_cost_model` to a security-relevant comparison primitive on both sides
of the gate (expected model AND caller model both flow through it).
**Fix:**

```python
def _require_cost_str(value: object, field_name: str) -> str:
    if not isinstance(value, str) or value == "":
        raise TypeError(f"{field_name} must be a non-empty string, got {value!r}")
    return value
```

and use it in place of the three `str(...)` calls in `build_cost_model`.
Note: verify no existing fixture relies on non-str coercion before shipping
(all phase6/phase7.1 fixtures use strings, so this is safe).

## Info

### IN-01: `binding.py` docstring misattributes the `KeyError` source

**File:** `src/backtest/binding.py:16-17,52`
**Issue:** Both the module docstring and the function docstring state that
absent slice keys "propagate as bare `KeyError` from `build_cost_model`".
In fact the `KeyError` is raised one line earlier, by the slice
comprehension `{k: parameter_set.params[k] for k in COST_KEYS}` (line 54) —
`build_cost_model` is never reached on that path. Behavior matches the
locked D-02 decision either way; only the attribution is wrong, which could
mislead a future refactor (e.g. someone wrapping the `build_cost_model`
call in a try/except `KeyError` and believing they covered the slice path —
they would, coincidentally, since both statements share the function scope,
but for the wrong reason).
**Fix:** Reword to "Absent slice keys raise bare `KeyError` from the
registry-slice lookup (`parameter_set.params[k]`), before `build_cost_model`
runs — fail closed, never silent defaults (D-02)."

### IN-02: Bare `KeyError` carries no set-identity context

**File:** `src/backtest/binding.py:54`
**Issue:** On the missing-slice path the raised `KeyError` contains only the
key name (e.g. `'funding_treatment'`). In a batch-assembly log this does not
identify which `strategy_id/parameter_set_id` was unbindable. The bare-type
lock from D-02/D-05 must be respected — do NOT translate into
`CostModelBindingMismatch` — but the payload can be enriched while keeping
the type.
**Fix (optional, preserving the lock):**

```python
try:
    registry_slice = {k: parameter_set.params[k] for k in COST_KEYS}
except KeyError as exc:
    raise KeyError(
        f"{parameter_set.strategy_id}/{parameter_set.parameter_set_id} "
        f"lacks cost key {exc}"
    ) from exc
```

Type stays `KeyError`; message names the set.

### IN-03: Mismatch message names hashes but not the divergent keys

**File:** `src/backtest/binding.py:56-61`
**Issue:** `CostModelBindingMismatch` reports both hashes plus set identity,
which is sufficient for refusal but forces manual per-key diffing during
debugging (compute both canonical payloads, compare). A diagnostic hint
listing which of the seven keys differ would shorten that loop without
touching the decision logic (comparison stays hash-string-only per D-05;
the hint is display-only, computed by comparing per-key canonical bytes,
never by Decimal `==`).
**Fix (optional):** After the hash comparison fails, compute the differing
key names via per-key `canonical_bytes` comparison between
`registry_slice` and the caller's cost fields, and append
`differing_keys=[...]` to the message. Keep it out of the raise condition.

### IN-04: No dedicated match-case fixture for the breakout-retest family

**File:** `tests/test_backtest_binding.py`, `tests/fixtures/phase7.1/`
**Issue:** All four phase7.1 fixtures bind `trend-pullback/baseline-v3`.
`breakout-retest/baseline-v3.toml` ships the same seven cost values and is
only exercised indirectly (`test_cr06_experiment_id_differs_across_run_type_and_strategy_id`
assembles a breakout record with the gap cost dict). A typo in the breakout
v3 cost keys that still parses (e.g. `fee_rate_entry = 0.0003`) would be
caught today only via that indirect test, not by a gate-module fixture whose
name states the intent. D-05's minimum coverage (wrong fee, wrong string,
precision drift) is met; this is symmetry hardening.
**Fix (optional):** Add `tests/fixtures/phase7.1/match_breakout/input.json`
mirroring the match case with `strategy_id: breakout-retest`, plus a
parametrized accept test over both families.
