# Phase 10 — UI Design Contract (Report Design Contract)

> Visual and interaction contract for the Phase 10 "dashboard". Per CONTEXT D-04 the dashboard is an
> OFFLINE, DETERMINISTIC, GENERATED static report (Markdown primary + JSON sidecar) produced by a
> CLI over a pure Python renderer. It is NOT a web app: no FastAPI, no server, no JavaScript, no
> component library, no design-system install. This contract therefore specifies a document, not a
> screen: section order, table column contracts, emphasis conventions, copy strings, status
> semantics and byte-determinism rules. The pixel-oriented template sections (Spacing, Typography,
> Color) are kept for checker compatibility and mapped to their plain-text equivalents.
>
> Generated by gsd-ui-researcher (--auto: recommended defaults chosen, no questions asked).
> Every default below is tagged `[default]`; every value taken from upstream is tagged with its
> source (`D-0x`, `RESEARCH`, `METRICS`).

## Design System

| Property | Value |
|----------|-------|
| Tool | none (no shadcn; no web UI in this phase — D-04) |
| Preset | not applicable |
| Component library | none |
| Icon library | none — ASCII status tokens only (see Color / Status Semantics) |
| Font | none declared. Report is viewed in an operator's Markdown viewer or terminal; all alignment-sensitive content is in fenced code or GFM tables, so no font is assumed. Monospace is assumed only for fenced blocks |

| Secondary artifact | JSON sidecar (machine-readable, same digest) |
| HTML | NOT produced in Phase 10 `[default]`. Rationale: HTML adds an escaping surface (RESEARCH Security) and a color channel that must never be the sole carrier of meaning. | Charts | none `[default]`. D-04 makes charts optional; the contract is tables only. Distribution data (R histograms, delay buckets) is rendered as bucket tables, not images |
| Telegram | optional one-way plain-text pointer only (see Copywriting: Telegram pointer). Never a decision surface, never buttons, never callback data (D-04) |

## Report Structure (section order — fixed, prescriptive)

The report is ONE document. Section order is constant regardless of data (empty sections still render,
with their empty-state copy). H1 appears once; H2 per numbered section; H3 per subsection.

| # | H2 heading (exact text) | Content | Always rendered |
|---|--------------------------|---------|-----------------|
| 0 | H1: `Journal Depth + Kill-Gate Report` | Header block (below) | yes |
| 1 | `## 1. Kill Gate` | Gate state banner, budget progress, clock provenance, per-family acceptance matrix, NO_TRADE counts by reason category | yes |
| 2 | `## 2. Evidence Overview` | Evidence kinds present (BACKTEST / PAPER / LIVE), counts, INCOMPLETE totals; never pooled | yes |
| 3 | `## 3. Full Report (unsliced)` | Complete metric block per evidence kind: counts, R distribution with uncertainty, MFE/MAE, execution quality | yes |
| 4 | `## 4. Dual Universe: Live-5 vs Research` | The section-3 metric block rendered side by side per universe | yes |
| 5 | `## 5. Approval-Delay Impact` | System / User execution / Opportunity reports side by side + delay buckets | yes |
| 6 | `## 6. Execution Quality` | Latency legs, fill %, wait-to-fill, expiry-without-fill, entry deviation | yes |
| 7 | `## 7. MFE / MAE` | Price and R excursion, time-to-extreme, METRICS §6 descriptive distributions | yes |
| 8 | `## 8. Robustness Slices` | One H3 per dimension, each table starts with the unsliced `ALL` row | yes |
| 9 | `## 9. Incomplete and Excluded Inputs` | Every INCOMPLETE bucket with reason and count; zero-risk exclusions; unmatched joins | yes |
| 10 | `## 10. Provenance` | Full evidence provenance and vocabulary constants | yes |

Rationale for order `[default]`: the kill gate is the terminal, one-way governance output, so it is first;
the unsliced Full Report (section 3) precedes every sliced view so the full picture is never below a
favorable-looking slice (JRN-01, D-02). Section 4 (dual universe) comes before the deep-dive sections so
the live-5 "no data" reality is visible before detail. No section may be collapsed, omitted, or moved
below a slice by any data condition ("full-report-always-visible" rule).

### Header block (directly under H1, exact field order)

Rendered as a two-column GFM table (`Field | Value`) so it is legible as plain text:

| Field | Value format |
|-------|--------------|
| Report digest | `sha256:<64 hex>` (digest of the report dataclasses, see Determinism) |
| As of (UTC) | `YYYY-MM-DDTHH:MM:SS+00:00` |
| As of (display) | `YYYY-MM-DD HH:MM:SS +07:00 (Asia/Ho_Chi_Minh)` |
| Timezone note | fixed sentence: `Stored and computed values are UTC. Display times are Asia/Ho_Chi_Minh (UTC+07:00, no DST).` |
| Generator | `src.analytics.cli` + analytics schema version string (e.g. `analytics-schema/1`) |
| Read-only statement | fixed sentence: `This report is read-only. It never changes parameters, orders, or approvals, and it never enables live trading.` |
| Kill gate state | state token, repeated here so it is the first data line a reader sees |
| Live orders | current posture token from `LIVE_ORDERS_DISABLED` journal events, or `UNKNOWN` (see Status Semantics) |

No generation wall-clock time, hostname, username, or absolute path may appear anywhere in the report.

## Section 1 layout: Kill Gate

Order inside `## 1. Kill Gate` (fixed):

1. **State banner** — a single blockquote, first line of the section:
   `> **KILL GATE STATE: <STATE>** — <one fixed sentence per state, see Copywriting>`
2. **Budget progress** — table `Budget | Required | Actual | Status`:
   - row `Independently specified families tested` | `3` | `<n>` | `MET` / `NOT_MET`
   - row `Research months elapsed` | `6 calendar months` | `<m>` (Decimal, 1 dp, plus whole calendar months + days) | `MET` / `NOT_MET`
   - row `Any family passing acceptance` | `none required` | `<count TESTED_PASS>` | informational
   - Rule row beneath the table (plain sentence): `INSUFFICIENT_EDGE requires BOTH budgets met AND no passing family (D013).`
3. **Clock provenance** — table `Field | Value`: `Research clock start (UTC)`, `Source` (protocol header path and field), `Freeze commit`, `Commit author date`, `Earliest possible INSUFFICIENT_EDGE (UTC)`, `Evaluated at (UTC)`, `Evaluated at (display)`.
4. **Family acceptance matrix** — see Table Column Contracts K-2.
5. **NO_TRADE by reason category** — see K-3.
6. **Decision references** — bullet list of `decision_ref` values that put a family in `TESTED_PASS` / `TESTED_FAIL`, or the fixed sentence `No recorded family decisions.`
7. **Enablement effect** — one sentence per state (Copywriting), always followed by `Live trading is never enabled by this report.`

Kill-gate view always shows BOTH universes: K-2 and K-3 each carry a `Live-5` and `Research universe` column group (empty group cell text `no data`).

## Table Column Contracts

Global table rules (apply to every table):
- GFM pipe tables; header row + alignment row; one blank line before and after.
- Alignment: text columns left (`:---`), numeric columns right (`---:`).
- Column order is fixed by this contract; a column is never dropped for empty data (cell shows `no data` or `INCOMPLETE`, see Copywriting).
- Row order is always a documented stable key order, NEVER favorability (D-02). `UNKNOWN` and `INCOMPLETE` rows are pinned last, in that order.
- Max 9 columns per table `[default]`; wider data is split into two tables sharing the row key. Sole exception: K-2b (Family + G01..G10 = 11 columns) stays one table so the gate matrix reads as a single grid; its legibility is the backstop check below.
- Every point estimate cell is rendered as `<value> [<lo>, <hi>] n=<n>` (Phase-6 bootstrap interval + sample size). When an interval is not computable (`n_r_valued < 2`) the cell is `<value> [interval absent] n=<n>`. A bare number is a contract violation.
- Every table caption is the preceding H3/H2 plus a one-line italic `Evidence: BACKTEST|PAPER|LIVE` (or `Evidence: BACKTEST | PAPER | LIVE (separate rows, not pooled)`).

### M-1 Core metric block (used in Sections 3 and 4, per evidence kind)

| Column | Type | Format |
|--------|------|--------|
| Metric | text | fixed labels: `Trades (n)`, `R-valued trades`, `Zero-risk excluded`, `INCOMPLETE`, `Mean R`, `Median R`, `Win rate`, `Expectancy (R)`, `Max drawdown (R)`, `Loss streak (max)` |
| Value | Decimal | estimate + interval + n per global rule |
| n | int | sample size behind the estimate |
| Low-n | token | `LOW_N` or empty |
| Note | text | short fixed string, e.g. `interval absent` |

Fixed constants shown in Provenance: `LOW_N_THRESHOLD = 30` (display flag only, not an acceptance threshold) `[default, RESEARCH A2]`, bootstrap `resamples`, `base_seed`.

### U-1 Dual-universe side-by-side (Section 4; reused inside K-2/K-3)

Two universes are columns of ONE table so they sit side by side in plain text:

| Metric | Live-5 value | Live-5 n | Research value | Research n | Low-n (Live-5 / Research) |
|--------|--------------|----------|----------------|-----------|---------------------------|

- Live-5 universe symbols line (fixed, above the table): `Live-5: BTCUSDT, ETHUSDT, BNBUSDT, SOLUSDT, XRPUSDT`. `Research universe: <sorted symbols> (universe hash <first 12 hex>; VERIFIED|UNVERIFIED_UNIVERSE)`.
- An empty live-5 slice renders `no data` in every value cell and `0` in n, with a one-line note under the table: `Live-5 slice has no rows for this evidence kind. Nothing is imputed or hidden.` The table and its rows are still rendered.
- If `weak_live_universe_rejection` (Phase-6 `DualUniverseSection`) is true, add a line: `Weak live-5 universe: research-universe results alone do not support acceptance (BACKTEST_SPEC §10.1).`

### D-1 Approval-delay impact (Section 5)

Three reports side by side per metric block (METRICS §3):

| Metric | System (all valid signals) | User execution (approved only) | Opportunity (skipped/expired) |
|--------|---------------------------|--------------------------------|------------------------------|

- Rows: `Signals (n)`, `Mean R`, `Expectancy (R)`, `Win rate`, `INCOMPLETE`. Opportunity hypothetical-outcome cells are `INCOMPLETE (no hypothetical outcome)` unless a simulator adapter supplied one.
- Followed by delay-bucket table `Signal-to-approve bucket | n | Mean R | Low-n`, buckets in fixed order `<1m`, `1-5m`, `5-30m`, `>=30m` `[default, RESEARCH A2]`, LIVE rows only.
- PAPER evidence rows carry the label `SYNTHETIC LAG (APPROVAL_DELAY_LAG_SECONDS=30)`; paper delay is never rendered as a measured latency and never appears in the bucket table (RESEARCH P2).
- Descriptive sentence, fixed: `Differences between columns describe selection and timing effects only.`

### E-1 Execution quality (Section 6)

| Leg / metric | n measured | n INCOMPLETE | Mean | Median | p90 | Unit |
|--------------|-----------|--------------|------|--------|-----|------|

Fixed row order and labels:
1. `Signal created -> seen` — always `INCOMPLETE (NO_SEEN_TIMESTAMP)` until a real VIEWED source exists; row is still rendered (RESEARCH P1)
2. `Signal created -> delivery requested (proxy)`
3. `Delivery requested -> approved`
4. `Signal created -> approved`
5. `Approved -> order placed`
6. `Order placed -> filled (wait-to-fill)`
7. `Fill %` (unit `%`)
8. `Expiry without fill rate` (unit `%`)
9. `Entry deviation (price, signed; positive = worse)`
10. `Entry deviation (bps of intended)`

Latency unit `s` (Decimal seconds, 1 dp). Each row is labelled by evidence kind via its own table (one E-1 per evidence kind that has data; kinds with no data render a single `no data` row set, not a missing table).

### X-1 MFE / MAE (Section 7)

| Measure | n | Mean | Median | p90 | Unit | Low-n |
|---------|---|------|--------|-----|------|-------|

Rows in fixed order: `MFE (price)`, `MAE (price)`, `MFE (R)`, `MAE (R)`, `Time to MFE`, `Time to MAE`, `Holding duration`. Followed by the METRICS §6 descriptive tables, each headed by its question as a neutral label (never a suggestion):
- `MFE (R) of stop-loss exits` (how far losers ran first)
- `MAE (R) of take-profit exits`
- `MFE (R) vs realized R (give-back)`
- `Holding duration distribution`

A fixed footer sentence under Section 7: `These distributions are descriptive. They imply no change to take-profit, stop-loss, entry, or holding rules.` MFE/MAE window convention line (RESEARCH A6): `Window: entry minute through exit minute, inclusive, 1m high/low. Trades without 1m coverage are counted as INCOMPLETE.`

### S-1 Robustness slice (Section 8, one table per dimension)

Dimensions in fixed order: `symbol`, `month`, `quarter`, `session`, `direction` (long/short), `volatility regime`, `trend/range regime`, `strategy version` (METRICS §5, D-02).

| Slice key | n | R-valued n | Mean R [interval] | Win rate | Expectancy (R) | Low-n | Evidence |
|-----------|---|------------|-------------------|----------|----------------|-------|----------|

- FIRST data row of every S-1 table is `ALL (unsliced)` — the full report, identical to Section 3 values. It is never omitted or moved.
- Then slice rows in ascending stable key order (`symbol` A-Z; `month`/`quarter` chronological; `session` in fixed order `ASIA`, `EUROPE`, `US`; `direction` `LONG` then `SHORT`; regimes alphabetical; `strategy version` lexicographic). Then `UNKNOWN`, then `INCOMPLETE`, always last.
- Slice count is stated in the H3 line: `### 8.1 Symbol (<k> slices, n=<total>)`.
- Low-n slices are flagged `LOW_N` in the Low-n column and stay in place. They are never hidden, dropped, or reordered.
- A dimension with no tagged data renders the `ALL` row plus one `UNKNOWN` row with the full count (never omitted). Session bands `[default, RESEARCH A1]`: ASIA 00-08, EUROPE 08-16, US 16-24 (UTC hour of entry time); `volatility regime` is `UNKNOWN` until a derivation lands.

### K-2 Family acceptance matrix (Section 1)

Rows = families in fixed order `trend-pullback`, `breakout-retest`, `range-mr` (then any further registry families alphabetically). Two tables:

Table K-2a `Family | Independent | Sheet hash (12) | Param sets | Experiments | Status | Decision ref | Universe`:
- `Independent`: `YES` / `NO` / `UNKNOWN` (distinct strategy_id + 7-slot sheet + distinct sheet hash; baselines excluded, RESEARCH Family registry)
- `Status`: `NOT_TESTED` | `TESTED_FAIL` | `TESTED_PASS`; `Decision ref` is required text for the latter two and shows `MISSING` in a non-empty-required cell otherwise
- Shared-component note beneath the table (RESEARCH Open Question 2): `Families A and C share the regime detector; B reuses the 4H direction gate. Shown for transparency; independence is decided by the registry test, not this note.`

Table K-2b gate matrix `Family | G01 | G02 | ... | G10` with legend line under it: `G01 Deterministic rules, G02 No material look-ahead, G03 Costs modeled, G04 Not single-symbol/session, G05 OOS consistent, G06 Tolerable drawdown, G07 Reproducible, G08 Interval uncertainty, G09 No single-point dependence, G10 Baseline-compared`. Cell values only from the vocabulary `MET`, `NOT_MET`, `PENDING_THRESHOLD_TBD`, `NOT_EVALUATED` (RESEARCH P3). Judgement gates (G05, G06 and threshold parts of G04/G09) render `PENDING_THRESHOLD_TBD`. No cell is ever rendered as a pass by inference.

### K-3 NO_TRADE counts by reason category (Section 1)

| Reason category | Live-5 n | Research n | All n |
|-----------------|----------|-----------|-------|

Rows in fixed order (RESEARCH_PROTOCOL §NO_TRADE): `regime filter`, `RR floor`, `open-position conflict`, `data unavailability`, `kill-gate trip`, then `UNMAPPED` (any reason code not in the five categories; count is shown, never dropped). Row `Total`. Empty cells render `0` (a count) and, where the whole universe has no records, `no data`.

### P-1 Provenance (Section 10)

Field/Value table, fields in fixed order: `strategyVersion`, `parameterSetId`, `parameterSetHash`, `experiment identity (six-field: experiment_id, strategy_version, parameter_set_id, parameter_set_hash, data_snapshot_id, code_version, cost_model_hash)`, `universe hash`, `dataset/version identifiers`, `epoch_id (paper)`, `APPROVAL_DELAY_LAG_SECONDS`, `LOW_N_THRESHOLD`, `resamples`, `base_seed`, `slice vocabulary version`, `session bands`, `evidence kinds present`. Multiple experiments render as sub-rows keyed by evidence kind, sorted by `experiment_id`. Hashes shown as first 12 hex with the full hash in the JSON sidecar.

## Spacing Scale

Not pixel-based. Spacing is expressed in text units so it is reproducible byte-for-byte. Declared values (all multiples of 1 line; the unit-of-4 rule is not applicable to a plain-text medium):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 0 blank lines | Between a table's header row and body (none) |
| sm | 1 blank line | Between any two blocks (paragraph, table, blockquote, fenced block); after every heading |
| md | 1 blank line + `---` rule + 1 blank line | Between H2 sections |
| lg | 2 blank lines | Never used |
| Indent | 0 spaces | Tables and paragraphs are never indented; nested bullets use 2 spaces |
| Column padding | 1 space on each side of `|` | Every pipe-table cell |

Exceptions: none. A single trailing LF ends the file; no trailing spaces on any line (a determinism rule, see below).

## Typography

Markdown has no font sizes. The four "sizes" are heading levels; the two "weights" are normal and bold. No italics-as-third-weight beyond the fixed `Evidence:` caption line. `[default]`

| Role | Rendering | Weight | Line height |
|------|-----------|--------|-------------|
| Display | `#` H1, used exactly once (report title) | bold (heading) | viewer default |
| Heading | `##` H2 numbered sections; `###` H3 subsections (H3 numbered `N.k`) | bold (heading) | viewer default |
| Label | `**bold**` for status tokens, state names, banner text, `Total` rows | bold | viewer default |
| Body | Plain paragraphs, table cells, bullets | normal | viewer default |

Rules:
- No H4 or deeper. No emoji, no non-ASCII characters in structural text (labels, tokens, headings). Prose uses plain ASCII hyphen and `->` arrows; the `—` em dash is permitted ONLY inside fixed banner sentences shown in this spec. Reason: Windows console/encoding safety and byte-stability.
- Inline code (backticks) for: identifiers, hashes, event types, enum values, file paths.
- Fenced code blocks are used only for the optional plain-text Telegram pointer preview and never for data tables.
- Emphasis never encodes favorability. Best/worst values are NEVER bolded, ordered first, or annotated (D-02).

Number formatting `[default]` (pinned; changing any digit count changes digests):

| Quantity | Format |
|----------|--------|
| Price, quantity, PnL | `format(Decimal, "f")`, no exponent, no thousands separator, quantized to the source precision |
| R-multiple, win rate as fraction, expectancy | 4 dp, half-even, `format(..., "f")` |
| Percent (fill %, expiry rate, coverage) | 2 dp with `%` suffix |
| Seconds | 1 dp, unit `s` |
| Bps | 2 dp, unit `bps` |
| Months elapsed | 1 dp |
| Integer counts | plain digits |
| Sign | leading `-` only; `+` never rendered; zero is `0.0000` never `-0.0000` |

## Color

No color in Phase 10. The report is Markdown; color is not available or relied on, so there is no 60/30/10 split, no accent, and no destructive color. `[default]` Meaning is carried entirely by text tokens so the report is fully legible in plain text, in a terminal, in a diff, and by a screen reader.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | not applicable (viewer default) | — |
| Secondary (30%) | not applicable | — |
| Accent (10%) | not applicable | — |
| Destructive | not applicable | Phase 10 has no destructive action (read-only report) |

Accent reserved for: not applicable. If a later phase adds HTML, it may add color only as a redundant second channel on top of the existing text tokens, and the token text must remain.

### Status semantics (text tokens; the entire "color" system)

Tokens are uppercase, wrapped in bold in banners and left plain inside table cells. They are the only status vocabulary permitted.

| Token | Meaning | Where used | Tone (fixed copy, no alarm language) |
|-------|---------|-----------|--------------------------------------|
| `WITHIN_BUDGET` | Fewer than 3 families tested OR fewer than 6 months elapsed; keep researching | Kill gate state | neutral |
| `PASSING_CANDIDATE` | A family has a recorded TESTED_PASS decision; evidence exists; does NOT authorize live | Kill gate state | neutral, explicitly non-authorizing |
| `INSUFFICIENT_EDGE` | Terminal: >=3 families tested AND >=6 months AND none passes. Valid outcome, not an error | Kill gate state | calm, factual, "process succeeded" |
| `TERMINAL` | Suffix shown next to `INSUFFICIENT_EDGE` only | Banner | — |
| `MET` / `NOT_MET` | Budget row status | Budget table | neutral |
| `PENDING_THRESHOLD_TBD` | Acceptance threshold not yet defined in the frozen protocol | Gate matrix | neutral |
| `NOT_EVALUATED` | No evidence evaluated for this gate | Gate matrix | neutral |
| `NOT_TESTED` / `TESTED_FAIL` / `TESTED_PASS` | Recorded human family decision | Family table | neutral |
| `LOW_N` | Sample size below `LOW_N_THRESHOLD`; flag only, row stays | Any n-bearing table | neutral |
| `INCOMPLETE` | Input missing or unmeasurable; counted, never imputed | Any metric cell / Section 9 | neutral |
| `UNKNOWN` | Tag/posture not derivable | Slice keys, live posture | neutral |
| `LIVE_ORDERS_DISABLED` / `LIVE_ORDERS_ENABLED` / `UNKNOWN` | Latest live-enable journal event | Header | neutral |
| `SYNTHETIC` | Constant-lag paper approval time, not a measurement | Approval-delay | neutral |
| `VERIFIED` / `UNVERIFIED_UNIVERSE` | Research-universe hash matches / does not match the ExperimentRecord `universe_hash` | Dual universe | neutral |

`INSUFFICIENT_EDGE` is rendered with the same visual weight as every other state (bold token in the banner). It must never be styled as an error, failure, or warning; it is a recorded, valid terminal outcome.

## Determinism and Rendering Rules (byte-identical output)

These are binding on `src/analytics/render.py` and its golden tests.

1. **Encoding/newlines:** UTF-8 without BOM; LF only; single trailing LF; files written with `newline="\n"` (Windows CRLF must not change bytes). No trailing whitespace on any line.
2. **No ambient state:** no `now()`, locale, hostname, username, absolute path, or process id in the output. Time comes only from the injected `as_of` and from stored UTC values.
3. **Ordering:** every list is sorted by an explicit documented total key; no dict/set iteration order, no built-in `hash()`. Journal inputs are ordered by `(occurred_at_utc, event_type, entity_id, journal_event_id)`, never by `journal_event_id` alone (callback ids are non-content-hash, RESEARCH Input Inventory).
4. **Decimals:** rendered only through the pinned formats in Typography; no exponent form (`1E+1`), no float, no locale grouping.
5. **Timestamps:** stored/computed UTC as `YYYY-MM-DDTHH:MM:SS+00:00`; display as `YYYY-MM-DD HH:MM:SS +07:00` via `zoneinfo.ZoneInfo("Asia/Ho_Chi_Minh")`, converted only at the render edge. Every timestamp shown in a table is the display form; the header shows both forms once, and the JSON sidecar stores UTC only.
6. **Escaping:** all DB/journal-sourced text (reason codes, notes, `payload_json` fragments) passes a single `md_cell()` escape: `|` -> `\|`, CR/LF -> single space, backtick and `<`/`>` neutralized, control characters stripped, length truncated at 200 chars with a fixed `...[truncated]` marker (count of truncations reported in Section 9). Raw `payload_json` is never embedded.
7. **Digest scheme:** `report_digest = sha256_hex` (canonical JSON via `src/domain/canonical.py`, rejects float/set) over the report dataclass tree in fixed section order plus provenance (as_of, seeds, vocabulary versions, evidence kinds). The Markdown embeds `report_digest` in the header table. The Markdown file cannot contain its own file hash, so the JSON sidecar carries `markdown_sha256` (sha256 of the exact `.md` bytes) alongside `report_digest`, `schema_version`, and the full section data. A verify step recomputes both.
8. **JSON sidecar:** `json.dumps(..., sort_keys=True, separators=(",", ":"), ensure_ascii=True)` plus a single trailing LF; Decimals as strings; datetimes as UTC ISO strings; enum values verbatim (`KillGateState` tokens, `ApprovalResult` PENDING/APPROVED/SKIPPED/EXPIRED).
9. **Bootstrap:** seeded `random.Random(base_seed + ordinal)` where `ordinal` is the slice's index in the sorted key list; seeds shown in Provenance.
10. **Secret posture:** payload keys are allow-listed; no API key, token, chat id, listen key, or exception message text appears (journal exception TYPE only). A render test scans output for secret-like substrings (mirror `tests/test_execution_secret_posture.py`).
11. **Pooling ban:** BACKTEST, PAPER, and LIVE each render in their own labelled table or column group. A pooled view is only allowed as an explicit sub-section titled `POOLED (labelled): <reason>` `[default: none in tracer]`.
