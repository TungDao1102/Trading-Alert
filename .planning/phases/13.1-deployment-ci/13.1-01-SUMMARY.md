## Note for the user

`src/risk/portfolio.py` (`check_portfolio`, lines ~302-303) assigns `warning_threshold_quote` and `stop_threshold_quote` and never reads them again. The thresholds themselves are used earlier, by `_derive_daily_state`, so the two aliases are dead leftovers rather than a missing check. I did not edit risk logic (D-18); the two F841 findings are silenced by a per-file ignore in `pyproject.toml` with a written reason. While reading the function I noticed something worth a look when risk code is next opened: when `daily_loss_quote is None`, `derived_state` is set to `NORMAL` ("unknown loss cannot derive"), so Gate 4 (DAILY_STOP block) does not trigger on an unknown daily loss. That is a possible latent daily-loss gating gap against the project's fail-closed rule. Whether callers can ever pass `None` in live mode was not investigated here.
