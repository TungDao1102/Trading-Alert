## Accomplishments

- **Dockerfile:** stages `uvbin` (uv 0.12.21), `rclonebin` (rclone 1.75.1), `runtime` (python 3.13.15-slim-bookworm), `ops`. No `# syntax=` line. `uv sync --frozen --no-dev` only. `RUN useradd --uid 10001 --create-home appuser` creates and chowns `/app/data/raw`, `/app/data/backup`, `/app/logs` in one layer so fresh named volumes inherit ownership (research finding 4). HEALTHCHECK (`--start-period=6m`) and CMD are exec form with `/app/.venv/bin/python`; no `uv run` at runtime. The `ops` stage copies rclone, installs rsync, openssh-client and PGDG `postgresql-client-17`, and aborts the build unless the downloaded PGDG key's primary fingerprint equals `B97B0AFCAA1A47F044F244A07FCC7D46ACCC4CF8`.
- **docker-compose.yml:** `name: trading`; `x-app` anchor (env_file `${TRADING_ENV_FILE:-.env}`, init, 30s grace, json-file 10m x 5); `x-database-env` anchor with the in-network URL on literal 5432. postgres publishes `127.0.0.1:${POSTGRES_PORT:-5432}:5432` only. `db-upgrade` (alembic upgrade head, owns the runtime build) gates `collector` through `service_completed_successfully`. `paper` and `live` exit with a message naming Phase 16 / Phase 24. `backup` (owns the ops build, rawdata read-only) and `ops` (toolbox) are in profile `ops`. Volumes: pgdata, rawdata, backupdata, logs. No container_name, no bind mounts.
- **.dockerignore:** `.env`, `.env.*`, `!.env.example`, VCS/tooling state, caches, `data`, `logs`, `backup`, `tests`. A test asserts it does not exclude anything the Dockerfile copies (`docs`, `scripts`, `src`, ...).
- **Tests:** 20 Dockerfile/.dockerignore text tests, 28 compose-config tests (default services, loopback port, `POSTGRES_PORT=5433` leaves the in-network URL on 5432, profile membership, placeholders, backup/ops mounts, logging/init/healthcheck on every service, only four POSTGRES vars needed even with all profiles, missing password fails config). Written first and observed red for both Task 1 and Task 2.
- **Docker-marked tests (4):** volume writability as UID 10001, image `User`/`Healthcheck`/`Cmd` metadata, ops tool versions (pg_dump/pg_restore 17, rclone v1.75.1, rsync, ssh), and a throwaway compose project proving `db-upgrade` exits 0 on a real postgres and `collector --healthcheck` exits 1 with `collector-health:` and no `ModuleNotFoundError`.
