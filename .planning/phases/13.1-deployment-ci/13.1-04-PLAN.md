<objective>
Build one redaction layer and wire it into the processes that run inside the compose stack with secrets in their environment, then document the credential variable names. This is the F-708 fix D-09 asks for, plus the OPS-06 rule that paper/test credentials use different names from live.

Purpose: success criterion 3 (secrets never appear in logs or error text) and OPS-02 (structured secret-free logging). Research found a real leak: libpq's conninfo error echoes the whole SQLAlchemy URL including the password, and httpx logs Telegram URLs that embed the bot token.
Output: src/ops/redaction.py, collector and backfill wiring, .env.example names, tests.

## Artifacts this phase produces (this plan)

- `src/ops/redaction.py`: `Redactor` (from_environ, scrub), module-level `scrub(text)`, `redact_processor` (structlog), `RedactingFilter` (stdlib logging), `install_global_hooks` (sys.excepthook, threading.excepthook, httpx/httpcore WARNING), `configure_logging()` (idempotent; returns the active Redactor).
- `src/data/collector.py`, `src/data/backfill_cli.py`: `configure_logging()` at the start of `main()`; collector stderr exception prints go through `scrub()`.
- `tests/conftest.py`: autouse fixture restoring structlog configuration, sys/threading excepthooks, root handlers and filters, and httpx/httpcore levels after each test.
- `.env.example`: BINANCE_TESTNET_API_KEY, BINANCE_TESTNET_API_SECRET, commented BINANCE_LIVE_API_KEY, BINANCE_LIVE_API_SECRET, BACKUP_S3_PROVIDER, BACKUP_S3_ENDPOINT, BACKUP_S3_REGION, BACKUP_S3_BUCKET, BACKUP_S3_ACCESS_KEY_ID, BACKUP_S3_SECRET_ACCESS_KEY, BACKUP_CRYPT_PASSWORD, BACKUP_CRYPT_PASSWORD2, IMAGE_TAG (D-25).
- `tests/test_redaction.py`, `tests/test_env_example.py`.

Backup and cutover entry points are wired by plans 06 and 07 (their own tests assert it), so this plan does not touch src/ops/backup.py. The one-shot `db-upgrade` service (alembic) is deliberately not wired: alembic's env.py calls fileConfig, which resets logging in that short-lived process, and it logs only alembic and SQLAlchemy INFO lines; this is the "accept for the one-shot" option of research Redaction design item 6, recorded in D050 by plan 11.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Process environment (secrets) -> logs, stderr, tracebacks | Any formatted exception or URL may carry secret material |
| Source tree -> remote repository | Anything committed is permanent and shared |
