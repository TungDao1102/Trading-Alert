## Accomplishments

- **Redactor:** collects values (length >= 8) of variables whose upper-cased name contains PASSWORD, SECRET, TOKEN, API_KEY, ACCESS_KEY, CRYPT or PRIVATE, plus the password of any URL-shaped value, with percent-encoded, decoded and JSON-escaped variants, longest first in one `re.escape` alternation. Shape rules need no environment: URL userinfo, Telegram token, `signature=<64 hex>`, `X-MBX-APIKEY` values, AWS key ids, PEM private key blocks (also truncated ones).
- **structlog:** `configure_logging()` installs `merge_contextvars, add_log_level, ISO UTC TimeStamper, format_exc_info, redact_processor, JSONRenderer`. The processor walks str/dict/list/tuple/set/bytes and masks keys named like password/secret/token/api_key/authorization/signature whatever the value.
- **stdlib and hooks:** `RedactingFilter` (on every root handler, no duplicates) scrubs the formatted message, arguments, traceback text and stack info. `sys.excepthook` and `threading.excepthook` are wrapped once and print a scrubbed traceback; httpx and httpcore are raised to WARNING.
- **Wiring:** `collector.main` and `backfill_cli.main` call `configure_logging()` as their first statement (AST-tested); the two collector exception prints use `scrub()`.
- **Test isolation:** autouse `_restore_logging_state` fixture restores structlog configuration, root handlers/filters/level, excepthooks and httpx levels.
- **.env.example:** `BINANCE_TESTNET_API_KEY/SECRET` active and empty; `BINANCE_LIVE_API_KEY/SECRET` commented; eight `BACKUP_S3_*`/`BACKUP_CRYPT_*` empty assignments with `rclone obscure`, off-VPS passphrase and "unrecoverable" guidance; `IMAGE_TAG=dev`; header states `.env` is created by `deploy/bootstrap.sh` with mode 0600. Existing names unchanged.

## Note for the user

- Once `configure_logging()` runs, the collector and backfill log lines are single-line JSON on stdout instead of the previous console format; stdlib log records go to stderr as `time level logger message`.
- Redaction is value-based: a secret only gets masked if it is in an environment variable with a secret-looking name, or has one of the known shapes. New secret variables should keep names containing PASSWORD, SECRET, TOKEN, API_KEY, ACCESS_KEY, CRYPT or PRIVATE.
- The backup crypt variables are placeholders that plan 06/07 consume; their values must be `rclone obscure` output, and the raw passphrase must live off the VPS.
- Windows: git warns LF will become CRLF for the new files (`core.autocrlf`), same as plan 03.
