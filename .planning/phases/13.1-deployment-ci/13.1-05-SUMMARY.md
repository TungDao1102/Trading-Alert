# Phase 13.1 Plan 05: Host bootstrap script and LF enforcement Summary

**`deploy/bootstrap.sh` turns a fresh Ubuntu 22.04/24.04 or Debian 12 host into a hardened Docker host (Docker apt repo, `trading` user, ufw, key-only SSH via a 00- drop-in verified with `sshd -t`/`sshd -T`, chrony with a drift bound, repo checkout at a ref, 0600 `.env`) idempotently, behind a key-presence lock-out guard, with `--dry-run`, and is tested through real bash against stub binaries.**

## Accomplishments

- **Preflight before any change:** OS matrix as data, unknown flags and missing `--ref`/`--secrets-file` die, root required unless `--dry-run`, secrets file validated (key names only in messages), and at least one `authorized_keys` line must be accepted by `ssh-keygen -l -f` (from `--authorized-keys` or the existing target file). Unsupported OS leaves the stub log empty.
- **Docker:** `docker.sources` in deb822 form (distro ID, codename, dpkg architecture, `Signed-By: /etc/apt/keyrings/docker.asc`), key fetched only when absent, five Docker packages installed only when dpkg reports them missing.
- **Hardening order:** user and docker group, `ufw default deny incoming`/`allow outgoing`, `ufw allow <port>/tcp` for every port `sshd -T` reports, then `ufw --force enable`, then the SSH drop-in. Drop-in is written atomically, checked with `sshd -t`, then `sshd -T` must show `passwordauthentication no`, `kbdinteractiveauthentication no`, `permitrootlogin no`, `pubkeyauthentication yes`; otherwise it is removed and the script exits before any reload. Reload is `systemctl try-reload-or-restart ssh`, followed by a keep-your-session-open warning.
- **Clock, checkout, .env:** chrony replaces timesyncd, `chronyc tracking` text is parsed (Leap status Normal, System time in ms vs `--max-drift-ms`, default 100). Checkout runs as `trading` through `runuser`, optional deploy key via `GIT_SSH_COMMAND`, `git checkout --detach <ref>`, no-op when HEAD already equals the ref. `.env` is installed `umask 077`, `install -m 0600 -o trading`, mode verified on POSIX.
- **Idempotency:** a second real run and a second dry run against configured state print no `+ ` line and call no mutating stub.
- **LF enforcement:** `.gitattributes` rules plus a CR scan of `deploy/` and `tests/fixtures/cutover/`, `git check-attr eol` per script, and an index-mode (100755) check; the gate globs `deploy/*.sh` so later plans are covered automatically.

## Deviations from Plan

1. **[Process] Test-first order.** Both test files were written and observed red/absent before the scripts for Tasks 1 and 2, and Task 3 tests were written before the chrony/checkout/env code. Task 1's skeleton steps only printed their plan lines; Tasks 2 and 3 replaced them.
2. **[Rule 1 - Bug, test harness] Vacuous first pass.** The first Task 1 run passed because stubs were written without the logging prologue, so "no mutation" assertions held trivially. Found while writing Task 2 tests, fixed (`_LOG` is now prepended to every stub), and the Task 1 tests were re-run non-vacuously before the Task 2 commit.
3. **[Rule 3 - Platform] Git Bash quirks.** `grep -q $'\r'` never matches under Git-for-Windows grep, so the CR check in secrets validation uses a bash pattern match on the file contents; `install -d -m 0700` fails on NTFS, so the test `install` stub drops `-m` on MINGW/MSYS (the logged argv still contains it, mode assertions are Linux-only).
4. **[Rule 2 - Performance] Shared first-run fixture.** Each bash run costs 4 to 8 seconds under Git Bash, so the suite initially took over 6 minutes. A module-scoped `golden` run is shared by step assertions and idempotency re-runs; failure variants keep their own runs.
5. **[Scope] Added assertion.** `pubkeyauthentication yes` is also asserted in `sshd -T` (the plan listed the other three). Added `--deploy-key` file existence and `--max-drift-ms` numeric validation in argument handling.

**Total deviations:** 1 process note, 4 adjustments. No architectural changes.

## Note for the user

- **Not verifiable on this machine, to be done on a real host (runbook, plan 11):** the actual ufw enable, sshd reload and second-session login, the Docker apt repository (key download, package install), chrony synchronising, ownership of the checkout and `.env`, and `.env` mode 600 on Linux (the mode test is skipped on Windows and runs in CI). Always run `--dry-run` first as root on the real host so read-only probes report truthfully.
- shellcheck is not installed here, so the `shellcheck -x` gate is skipped locally and will only bite in CI (strict mode turns the skip into a failure). I removed the obvious SC2086/source-path issues by hand but could not run it.
- `--ref` should be a tag or commit: an existing local branch name is resolved from the local clone and may be stale.
- On Windows git warns that LF will become CRLF for new files (`core.autocrlf=true`); the new `.gitattributes` rules force LF for deploy files regardless.
- OPS-02 and OPS-06 are intentionally not marked complete in REQUIREMENTS.md; that happens at phase end.
