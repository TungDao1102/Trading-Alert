<objective>
Extend `src/ops/backup.py` with the pieces a real restore needs (bundle verification, a restore that refuses bad input, a pg_dump/pg_restore path that works against the compose PostgreSQL 17 without leaking the password) while keeping the existing bundle format, `backup`, `drill` and `prune` behaviour (D-12, D-13).

Purpose: success criterion 6 ("restore.sh restores the latest bundle onto an empty host") needs a verified, refusing restore in Python so the shell wrappers stay thin. Research finding 3 showed today's pg_dump call passes a SQLAlchemy URL to libpq, which fails and echoes the password.
Output: new functions and subcommands in src/ops/backup.py, tests with injected fake runners (no PostgreSQL needed locally; the real pg_restore path runs in the docker drill test of plan 10).

## Artifacts this phase produces (this plan)

- `src/ops/backup.py` additions:
  - `verify_bundle(bundle_root) -> list[str]` (problems; empty means valid; set equality of manifest keys and files on disk excluding manifest.json, sha256 per file).
  - `libpq_target(database_url) -> LibpqTarget(url_without_password: str, env: dict[str, str])` (strips `+driver`, rejects non-postgresql schemes, percent-decodes the password into PGPASSWORD).
  - `restore_database(dump_path, *, database_url, force, pg_restore_runner, migrate_runner, expect_sha256=None)` and `restore_bundle(bundle_root, *, parquet_target, database_url, force, skip_db, pg_restore_runner, migrate_runner)`.
  - CLI subcommands: `verify --bundle-root P`; `dump --out F`; `restore-db --pg-dump F [--expect-sha256 H] [--force]`; `restore --bundle-root P --parquet-target D [--force] [--skip-db]`. Existing `backup`, `drill`, `prune` keep their flags and output lines.
  - Runner seams typed like the existing `PgDumpRunner`: `PgRestoreRunner = Callable[[Path, LibpqTarget], None]`, `MigrateRunner = Callable[[str], None]` (production: `[sys.executable, "-m", "alembic", "upgrade", "head"]` with DATABASE_URL in the child env and cwd at the project root).
- `tests/test_backup_restore.py`.

Cross-plan contract: plan 08 adds `push`, `pull`, `retain`, `scheduled` and `drill-remote` to the same CLI; plan 09 calls `dump` on the old host and `restore-db` on the new host; plan 10's restore.sh calls `pull` then `restore`.
