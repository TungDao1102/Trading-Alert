# Phase 13.1 Plan 06: Bundle verification and refusing restore Summary

**`python -m src.ops.backup` now verifies a bundle by sha256 and set equality, restores it through pg_restore, a never-overwriting Parquet copy and `alembic upgrade head` (refusing tampered bundles and non-empty targets), and talks to PostgreSQL with a password-free libpq URL plus `PGPASSWORD`.**

## Accomplishments

- **verify_bundle / `verify`:** hashes every manifest entry, reports missing files, sha256 mismatches, files on disk that are not in the manifest (the root `manifest.json` excluded) and unsafe manifest keys; one stderr line per problem naming the relative path; prints `verify-OK` on success.
- **restore_bundle / `restore`:** verification first, then a full preflight (target is not the bundle or inside it, Parquet target empty or `--force`, every planned file either absent or byte-identical, URL scheme valid, database empty or `--force`), then pg_restore, the Parquet copy (temp name plus `os.replace`, hash checked before the rename, never overwrites) and the migrate runner. `--skip-db` restores Parquet only.
- **libpq_target:** `postgresql+psycopg://u:p%40ss@h:5432/db` becomes `postgresql://u@h:5432/db` plus `PGPASSWORD=p@ss`; a `password=` query parameter is moved too; other schemes raise `ValueError` naming only the scheme; `LibpqTarget.env` is excluded from `repr`.
- **Runners:** `_prod_pg_dump_runner` (`PG_DUMP_BIN`), `_prod_pg_restore_runner` (`PG_RESTORE_BIN`, `--clean --if-exists --no-owner --no-privileges --exit-on-error`) and `_prod_migrate_runner` (`sys.executable -m alembic upgrade head`, cwd at the project root, `DATABASE_URL` in the child env).
- **dump / restore-db:** `dump --out F` writes `F` and `F.sha256` (`<hex>  <name>`); `restore-db --pg-dump F [--expect-sha256 H] [--force]` checks the hash and database emptiness before pg_restore, then migrates.
- **Hygiene:** `backup()` and `write_manifest` skip `.<name>.<pid>.tmp` files; the pg_dump-before-Parquet order is documented in the `backup()` docstring and covered by a call-order test; `main()` calls `configure_logging()` first and prints exceptions as one scrubbed line (a failed subprocess prints only `<binary> failed with exit status N`).

## Deviations from Plan

1. **[Process] Task boundary blurred.** `restore_bundle` needs `LibpqTarget`, `restore_database`, the pg_restore/migrate runner seams and the emptiness probe to be complete, so those landed in the Task 1 commit together with the production pg_restore and migrate runners. Task 2 then added its tests red first (11 failures observed) and implemented the pg_dump rewrite, `_run_pg_tool`, `dump`, `restore-db`, tmp-file skipping, logging wiring and error scrubbing. Task 1's tests were written red (import error) before any implementation.
2. **[Rule 2 - robustness] Extra safety checks beyond the plan:** unsafe manifest key rejection (path traversal), refusal when `--parquet-target` contains or sits inside the bundle, refusal when two bundle roots disagree on a relative path, `password=` query parameter handling in `libpq_target`.
3. **[Design] Extra test seams on `main()`:** keyword arguments `pg_dump_runner` and `data_probe` in addition to the planned `pg_restore_runner` and `migrate_runner`. The probe seam exists because libpq rejects the SQLite URLs used in tests while the emptiness check must still be tested through real SQLAlchemy inspection (`_tables_with_rows` is tested directly on SQLite).
4. **[Behaviour change] Uncaught errors in the existing subcommands** (`backup`, `drill`, `prune`) now print one scrubbed `error: ...` line and exit 1 instead of a traceback (exit 1 as before). Flags and success output lines are unchanged.

## Note for the user

- The real `pg_restore` and `alembic upgrade head` path has not run against PostgreSQL 17 here; that is the docker drill test in plan 10. Until then it is covered by argv/env unit tests with a spied `subprocess.run`.
- `restore` and `restore-db` read the database URL from `DATABASE_URL_SYNC`, falling back to `DATABASE_URL`, like `backup`. `pg_restore` must be version 17 (or newer) to read a PG 17 dump; the `ops` image installs the 17 client (plan 02).
- `--force` allows a non-empty Parquet target or database but a Parquet file that already exists with different content still aborts the restore: raw files are immutable (D-04).
