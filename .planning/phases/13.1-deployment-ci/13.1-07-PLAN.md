<objective>
Build the typed cutover verifier the migration script prints at the end: it proves no Parquet file and no watermark row was lost across a host switch and reports the OI gap the switch caused, in minutes, against a configurable threshold (D-14, D-22).

Purpose: success criteria 5 and 7 judge the migration by file-set equality with hashes, watermark rows and a bounded, reported gap. Keeping this logic in Python (not bash) makes it testable here; plan 09 calls it from deploy/migrate.sh and in the two-environment docker test.
Output: src/ops/cutover.py and tests/test_cutover.py.

## Artifacts this phase produces (this plan)

- `src/ops/cutover.py` (strict typing; imports src.data.coverage, src.db.models, src.ops.redaction, stdlib, SQLAlchemy for the watermark read only):
  - `fingerprint(raw_root: Path) -> dict[str, str]`
  - `watermark_snapshot(database_url: str) -> dict[str, str]` (key "SYMBOL|data_class", value ISO-8601 UTC with "Z")
  - `compare_files(old, new) -> FileDiff(missing: tuple[str, ...], changed: tuple[str, ...], added: tuple[str, ...])` (added files are expected new ticks, not loss)
  - `compare_watermarks(old, new) -> WatermarkDiff(lost, regressed)`
  - `oi_gaps(raw_root, symbols, window_start_utc, window_end_utc) -> tuple[SymbolGap, ...]` with `SymbolGap(symbol, max_gap_minutes: int, ranges: tuple[GapRange, ...])`
  - `build_report(...) -> CutoverReport` with `exit_code` (0, 1 or 3), `render_text(report) -> str`, JSON output via `--json-out`
  - CLI `python -m src.ops.cutover fingerprint|watermarks|report`; report flags `--old-fingerprint --new-fingerprint --old-watermarks --new-watermarks --raw-root --max-gap-minutes 60 --window-end <ISO UTC> --json-out`.
- Window rule: start = (minimum old OI last_tick_utc) minus 2 cadences; end = --window-end, default now floored to the 5-minute cadence. Symbols = those with an old "oi" watermark.
</objective>
