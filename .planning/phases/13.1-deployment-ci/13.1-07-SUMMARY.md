# Phase 13.1 Plan 07: Cutover verifier Summary

**`python -m src.ops.cutover` proves a host switch lost no Parquet file and no watermark row (set comparison of path and sha256) and reports the OI gap the switch caused in minutes, using the single `coverage.gap_ranges_for_files` gap definition, with exit codes the migration script can act on.**

## Accomplishments

- **Snapshots:** `fingerprint` hashes every `*.parquet` under the raw root (posix relative keys, atomic-write temp files skipped); `watermark_snapshot` reads `collector_watermarks` with a sync SQLAlchemy engine and renders `SYMBOL|data_class -> ISO UTC Z` (naive SQLite datetimes treated as UTC like `collector._tick_epoch_ms`).
- **Comparison:** `compare_files` yields missing, changed and added (added are new ticks, never loss); `compare_watermarks` yields lost and regressed.
- **OI gap:** window start is the minimum old OI watermark minus 2 cadences, end is `--window-end` or now floored to 5 minutes; symbols are those with an old `oi` watermark. Per symbol, `gap_ranges_for_files(series="oi", step 300000, max_step 2 cadences)` over `observed_at_utc`; minutes per hole = `(end - start + step) // 60000` in integer epoch ms; the symbol figure is the maximum. A trailing hole counts (46 minutes with no new tick at window end 11:46).
- **Exit precedence:** 1 (any loss) over 3 (worst gap strictly above `--max-gap-minutes`, default 60) over 0. `render_text` prints the verdict, per-symbol gap lines and the three D-22 statements; `--json-out` writes the same facts as sorted-key LF JSON.
- **Safety:** `configure_logging()` is the first call in `main()`; errors print only `cutover: <ExceptionType>` through `scrub()`; no URL is ever printed.
