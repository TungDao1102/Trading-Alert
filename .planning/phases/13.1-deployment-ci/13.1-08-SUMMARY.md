# Phase 13.1 Plan 08: Encrypted off-host backups with retention Summary

**`python -m src.ops.backup` now pushes verified snapshots to any S3-compatible store through rclone with a crypt layer (config only from `BACKUP_S3_*`/`BACKUP_CRYPT_*`), keeps 7 daily / 4 weekly / 6 monthly snapshots with a pure outage-safe function proven against a 400-day oracle, and pulls, schedules and drills restores with a sentinel that makes a wrong key an error instead of an empty store.**

## Accomplishments

- **Adapter (`src/ops/backup_remote.py`):** `rclone_env` maps the eight variables to `RCLONE_CONFIG_BACKUPS3_*` and `RCLONE_CONFIG_BACKUPS3CRYPT_*` and raises `RemoteConfigError` naming every missing variable. The production runner passes the mapped env only to the child process; errors carry the exit code and a scrubbed, bounded stderr excerpt.
- **Sentinel guard:** every push, pull, retain and drill first `cat`s `_sentinel/sentinel.txt` through the crypt remote and compares it. Exit 3, an empty read and a mismatch all fail. `--init-remote` writes the sentinel only when the read says "not found", the decrypted snapshot listing is empty and the raw ciphertext bucket listing is empty.
- **Push:** verify bundle -> sentinel -> `copy parquet --immutable` -> `copyto pg.dump` -> `copyto manifest.json` -> `cryptcheck` (with `/pg.dump` and `/manifest.json` filters). Never a sync, move or delete against the remote.
- **Retention:** `select_retained` (newest per UTC day / ISO week / month for the N most recent periods that have a snapshot, newest overall always kept, unparseable names untouched). `apply_retention` checks the sentinel, treats an empty listing as an error and `rclone purge`s only `snapshots/<id>`; `--dry-run` lists only.
- **Pull:** copies one snapshot, reads its manifest, fetches exactly the named Parquet files with `--files-from-raw`, runs `verify_bundle` before returning; refuses a non-empty `--dest` before any remote call.
- **Scheduled / drill-remote:** `scheduled` = backup (pg_dump first) -> verify -> push + cryptcheck -> retention. `drill-remote` = backup -> push -> pull to the scratch root -> `<db>_drill_<YYYYMMDDHHMMSS>` created through an AUTOCOMMIT admin connection -> `restore_database` -> equal `collector_watermarks` row counts -> database dropped in a `finally`.
- **Real rclone test:** `tests/test_docker_backup_remote.py` runs the pinned rclone 1.75.1 image as `rclone serve s3` and as the client: init + two pushes (no existing object changed, store holds no plaintext names), list, pull, `cryptcheck` pass and fail, retention over nine planted days (dry run, then real, Parquet intact), and wrong-key refusal for push, retain, pull and `--init-remote`.

## Deviations from Plan

1. **[Rule 2 - crash safety] Upload order.** The plan listed pg.dump and manifest.json before the Parquet copy. A crash between them would leave a newest snapshot whose manifest names Parquet files that are not on the remote. Order is now Parquet, pg.dump, manifest.json, cryptcheck, so a snapshot looks complete only once its dependencies exist. Test: `test_push_uploads_manifest_last_so_a_snapshot_is_never_complete_before_its_files`.
2. **[Rule 2 - safety] `init_sentinel(runner, *, raw_remote)`** has a required keyword the plan did not list. With a wrong key an existing store looks "not found" and "empty" through the crypt remote, so `--init-remote` additionally requires the raw ciphertext bucket listing to be empty (`BACKUPS3:<bucket>`). Covered by a unit test and by the docker test.
3. **[Rule 1 - bug found by the oracle] `select_retained` slice.** The first draft sliced `periods[len - count:]`, which for fewer periods than the window start is negative and dropped snapshots. The 400-day oracle test caught it on the first run; fixed with `max(0, ...)` and a dedicated regression test.
4. **[Environment] No user-defined docker network.** The plan asked for a user network. On this machine's daemon, attaching a container to any user-defined network hangs and the container stays in "Created" (reproduced with an unrelated `sleep` container). The docker test uses the default bridge and the server container IP instead; the module docstring records why.
5. **[Design] Extra `main()` seams** `rclone_runner`, `now_utc`, `drill_ops` (in addition to the existing runner seams) so the five subcommands are tested end to end without rclone or PostgreSQL.
6. **[Design] CLI handlers live in `backup_remote.py`** (`cli_push`, `cli_pull`, `cli_retain`, `cli_scheduled`, `cli_drill_remote`); `backup.py` only registers parsers and dispatches with a lazy import (no import cycle, `tests/test_backup.py` literal checks stay green).
