<objective>
Write the provider-portable migration script and prove it end to end between two local Docker environments (D-14, D-15, D-20, D-21).

Purpose: success criteria 5 and 7: a fixed-order cutover that loses no Parquet file or watermark row and reports a bounded gap, with the old host shut down only by a human. Shell stays thin: data checks live in src/ops/cutover.py (plan 07), dump and restore in src/ops/backup.py (plan 06).
Output: deploy/migrate.sh, a stubbed ordering test, cutover fixtures and the docker-marked two-environment test (runs in the CI docker job; skips here where the app images cannot be built).

## Artifacts this phase produces (this plan)

- `deploy/migrate.sh`: `migrate.sh [--dry-run] [--max-gap-minutes N] [--wait-seconds 900] [--key-source PATH_OR_VOLUME] <old-ssh-target> <new-ssh-target|local>`. Step functions `preflight`, `presync`, `stop_old_collector`, `final_sync`, `snapshot_old`, `pull_artifacts`, `restore_new`, `start_new_collector`, `wait_first_tick`, `report`. Overrides for the harness, each defaulting to the real-host form: `MIGRATE_OLD_COMPOSE` (default ssh to old, then `docker compose --project-directory ${MIGRATE_OLD_DIR:-/opt/trading} -p ${MIGRATE_OLD_PROJECT:-trading}`), `MIGRATE_NEW_COMPOSE` (local `docker compose -p ${MIGRATE_NEW_PROJECT:-trading}` when new is `local`, else via ssh), `MIGRATE_RSYNC_SOURCE` (default `<old-ssh-target>`), `MIGRATE_RSYNC_PATH` (default `docker run --rm -i -v ${MIGRATE_OLD_PROJECT:-trading}_rawdata:/data/raw:ro -v ${MIGRATE_OLD_PROJECT:-trading}_backupdata:/data/backup:ro --entrypoint rsync trading-alert-ops:${IMAGE_TAG:-dev}`), `MIGRATE_REPORT_WINDOW_END` (optional ISO UTC passed to the report).
- Transfer layout: old raw store `/data/raw/` -> new `/app/data/raw/`; old `/data/backup/cutover/` (pg.dump, pg.dump.sha256, old-fingerprint.json, old-watermarks.json) -> new `/app/data/backup/cutover/`. The receiving rsync runs inside the new project's `ops` service as root (`--user 0:0`, so it can read a 0600 key and preserve UID 10001 ownership with -a), with the key source mounted read-only at /keys (id_ed25519 and known_hosts).
- `tests/fixtures/cutover/`: `Dockerfile.sshd` (FROM the pinned python:3.13.15-slim-bookworm digest; apt openssh-server and rsync; non-root `rsync` user; host keys generated at build), `sshd_config` (key-only, AuthorizedKeysFile /keys/id_ed25519.pub, no password, no root), `fake_collector.py`, `compose.cutover.yml` (override: collector command runs the fake collector in tick mode from a read-only fixture mount, restart "no"; FAKE_TICK_AT passed through from the test env).
- `tests/test_deploy_migrate.py` (stubs), `tests/test_docker_cutover.py` (docker-marked).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Old host -> new host (ssh plus rsync) | Research data and the database dump cross the network |
| Migration script -> old host control | The script can issue commands on the old host |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13.1-39 | Tampering | rsync deleting or overwriting immutable raw files | high | mitigate | No deletion option, --ignore-existing, temp files excluded; stub test asserts the flags on every rsync call |
| T-13.1-40 | Spoofing | Man-in-the-middle on the rsync ssh channel | high | mitigate | StrictHostKeyChecking=yes with an explicit known_hosts file; dedicated key mounted read-only |
| T-13.1-41 | Denial of service | Script shuts down or tears down the old host before the new one is proven | high | mitigate | Only `stop collector` on the old side; no down, poweroff or shutdown; human-shutdown notice; stub test bans those calls |
| T-13.1-42 | Information disclosure | Migration private key copied into an image or data volume | medium | mitigate | Key mounted read-only at run time, never copied; test keys live in a throwaway volume removed after the test |
| T-13.1-SC | Tampering | npm/pip/cargo installs | high | mitigate | No packages are installed; the sidecar uses the pinned python digest and distro apt packages only |
</threat_model>
