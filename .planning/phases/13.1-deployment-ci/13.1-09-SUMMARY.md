# Phase 13.1 Plan 09: Cutover migration script and two-environment proof Summary

**`deploy/migrate.sh <old> <new|local>` performs the D-14 cutover in a fixed, non-destructive order (append-only rsync over strict-host-key ssh, collector-only stop on the old host, hash-verified restore, first-tick wait, `src.ops.cutover report` exit code propagated), with the ordering and the no-deletion and no-shutdown rules proven through real bash with stubs here and the full two-Compose-project data proof written for the CI docker job.**

## Accomplishments

- **`deploy/migrate.sh`:** ten step functions in D-14 order (`preflight presync stop_old_collector final_sync snapshot_old pull_artifacts restore_new start_new_collector wait_first_tick report`), `--dry-run` through `lib.sh run()`, `--max-gap-minutes` (default 60), `--wait-seconds` (default 900), `--key-source`, `--report-only`. Old and new compose prefixes are arrays; `MIGRATE_*` overrides replace them for the harness. rsync runs in the new project's `ops` container as root with the key dir read-only at `/keys`, `-a --numeric-ids --ignore-existing --exclude '.*.tmp'`, `StrictHostKeyChecking=yes`, `UserKnownHostsFile=/keys/known_hosts`, and `--rsync-path` defaulting to `docker run` of the ops image with `<project>_rawdata` and `<project>_backupdata` mounted read-only. The dump hash is read from `pg.dump.sha256` on the new side and passed to `restore-db --expect-sha256`.
- **Safety:** no delete option anywhere, only `stop collector` on the old side, no down/poweroff/shutdown, the notice that a human shuts the old host down after a clean report prints for every report exit code, and a failure after the stop prints the exact `start collector` command to resume the old side.
- **`src.ops.cutover advanced`:** exit 0 when every old `|oi` watermark moved strictly forward, 1 while one has not (a missing row counts as not yet), 2 on unreadable input. Three unit tests.
- **Fixtures:** `Dockerfile.sshd` (same pinned python digest as the app image, openssh-server + rsync, UID 10001 `rsync` user, host keys at build), key-only `sshd_config` reading `/keys/id_ed25519.pub`, `fake_collector.py` (`seed` and `tick` through `_write_oi_snapshot` and `_advance_watermark`, `FAKE_TICK_AT`), `compose.cutover.yml` (collector command replaced, fixture mounted read-only, ops gets the same mount so the test can seed).
- **Docker test:** old project (schema + 13 ticks per symbol from 10:00) and new project (postgres only) from the real compose file, key volume + known_hosts via the ops image, sidecar on the new network with the old volumes read-only, `migrate.sh` driven by `MIGRATE_*`. Assertions use `sha256sum` and `psql` independently of the verifier, then check the report JSON (45 minutes for both symbols, exit 0) and a `--report-only --max-gap-minutes 30` re-run (exit 3). All containers, volumes and projects are removed in `finally`.

## Deviations from Plan

1. **[Rule 3 - blocking] New subcommand `advanced` in `src/ops/cutover.py` (plus 3 tests in `tests/test_cutover.py`).** The plan names the poll ("until every old OI watermark has advanced") but not where the comparison lives; those two files were not in `files_modified`. A shell or `python -c` comparison would have broken over ssh quoting and been untestable, so the check is a small Python subcommand with unit tests. Commit `980e4e3`.
2. **[Process] Tracer test-first was not strictly red before green.** The script and its tests were written in one pass; the tests were mutation-checked afterwards (see Verification) instead of observed red first.
3. **[Rule 2 - safety] Stale-artifact refusal and `--report-only` / failure-resume hint added** (see key decisions); none of them changes the plan's order or contract.
4. **[Design] `MIGRATE_NEW_DIR`, `MIGRATE_OLD_DIR`, `MIGRATE_KEY_SOURCE`, `MIGRATE_POLL_SECONDS`** are extra environment knobs; defaults are the real-host values.
5. **[Environment] The cutover docker test could not run here, and could not be validated end to end.** See the next section. It was written for the CI docker job and is statically checked only (ruff, collection, skip path).

## Notes for the user

- Prerequisite for a real cutover: both hosts on Phase 13.1 (ops image present), a migration key directory holding `id_ed25519` and `known_hosts` (generated for this purpose, authorised on the old host), `docker` access for the ssh user on the old host.
- Typical run on the new host: `deploy/migrate.sh --key-source ~/.ssh/trading-migrate trading@old.example local`; add `--dry-run` first to read the plan. Exit 0 means clean; shut the old host down by hand only then. After exit 3 (gap above threshold) the report is data, not a failure to retry: the OI hole is permanent loss.
- Windows: git warns LF will become CRLF for new files, same as earlier plans (`.gitattributes` forces LF for deploy files and the fixtures).
