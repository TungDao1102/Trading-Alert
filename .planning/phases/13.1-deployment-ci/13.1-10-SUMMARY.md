# Phase 13.1 Plan 10: Linux backup, restore, drill wrappers, systemd timer and reversible update Summary

**Four thin deploy scripts (backup with `--init-remote`/`--install-timer`, restore onto an empty host, Linux restore drill, update/rollback by recorded image ID) plus a daily persistent systemd timer, proven through real bash with stubs here and written as a three-step real-container drill (backup, drill, restore into a second empty project) for the CI docker job.**

## Accomplishments

- **backup.sh:** default `compose --profile ops run --rm -T backup /app/.venv/bin/python -m src.ops.backup scheduled`; `--init-remote` runs `backup --bundle-root data/backup/bundle` then `push --init-remote` (a failing first step stops the second); `--install-timer` writes `trading-backup.service` and `.timer` under `${TRADING_ROOT_PREFIX}/etc/systemd/system` with the checkout directory substituted, `daemon-reload` only when a file changed, then `enable --now trading-backup.timer`. A non-zero Python exit code is the wrapper's, so the oneshot unit fails visibly.
- **Units:** service is `Type=oneshot`, `User=trading`, after and requiring docker; timer is `OnCalendar=*-*-* 03:15:00 UTC`, `Persistent=true`, `RandomizedDelaySec=5m`.
- **restore.sh:** `up -d --wait postgres`, ops `pull --dest data/backup/restore-<ts>`, ops `restore --bundle-root <same dir> --parquet-target data/raw [--force]`, `up -d` unless `--no-start`; `--snapshot` is regex-checked and forwarded to pull.
- **backup-drill.sh:** one ops call, `drill-remote --scratch-root data/backup/drill-<ts>`; `scripts/backup-drill.ps1` untouched.
- **update.sh:** dirty tree refused first; state in `.deploy/last-good.env` (mode 0600, parsed not sourced); backup, `:rollback` tags, fetch, detached checkout, `--profile ops build`, `up -d`. Rollback checks the state file's format, verifies the `:rollback` images, checks out the recorded commit, re-tags, verifies the active tags, `up -d --no-build`, and warns that a migration is not undone.
- **Tests:** 41 stub-driven tests through real bash (order, flag forwarding, exit codes, idempotent unit install, thin-wrapper scan, update-then-rollback round trip with tag-modelling docker stub). Mutation checks: dropping `--no-build` and dropping the dirty-tree check each fail tests.
- **Docker drill:** a module-scoped fixture builds an `rclone serve s3` double, a seeded source project and an empty target project (both attached to the double by container name), runs the wrappers exactly as an operator would and compares `src.ops.cutover fingerprint` and `watermarks` of both projects.

## Deviations from Plan

1. **[Rule 3 - blocking] `compose_init` added to `deploy/lib.sh`** (not in `files_modified`). The wrappers must honour `TRADING_ENV_FILE` for compose interpolation as well as for `env_file:` (without `--env-file`, `${POSTGRES_USER:?}` would not see the second project's values), and four scripts need the same three lines.
2. **[Rule 2 - safety] Extra rollback check before changing anything.** The plan compares image IDs after re-tagging; the script also verifies the `:rollback` tags against the record first, so a stale or foreign tag aborts before the checkout and re-tag.
3. **[Rule 2 - safety] Update refuses to run without both local images** (nothing to roll back to) and rejects a ref starting with a dash; `--rollback` with `--skip-backup` is a usage error.
4. **[Design] Test seam `TRADING_DEPLOY_STATE_DIR`** replaces `.deploy` so the tests never write into the checkout; default is `<checkout>/.deploy`.
5. **[Design] `backup.sh` uses `-T`** (no pseudo-TTY) on every `compose run`, needed under systemd; the same for the ops calls.
6. **[Process] Task 1 was observed red before green; Task 2 scripts were written before their tests** and the tests were mutation-checked afterwards.
7. **[Process] Mode bits.** `git add` on this Windows checkout reset the three Task 2 scripts to 100644 (core.fileMode is false), so a follow-up commit `b2af9b1` sets 100755 in the index; the hygiene test now passes on the final tree.
8. **[Design] The second restore in the docker drill also passes `--no-start`**, so even a missing refusal could not start the real collector (which would call Binance).

## Deferred Issues

- `deploy/update.sh` overwrites `last-good.env` on every `--ref` run. After a half-failed update, running update again records the half-updated state; roll back first (or fix the cause) before retrying. Worth one RUNBOOK line (plan 11/12).
- `drill-remote` and `restore.sh` leave `data/backup/drill-<ts>` and `data/backup/restore-<ts>` in the `backupdata` volume (plan 08 noted this); the RUNBOOK should say to remove old ones by hand.
- Provider-side object versioning or object lock and an off-VPS heartbeat for the nightly backup (T-13.1-36, T-13.1-44) are operator controls for the RUNBOOK.
- CI: the docker job already selects `-m docker` (`.github/workflows/ci.yml` runs `uv run pytest -m docker`), so both cutover (plan 09) and drill tests run there; no workflow change was needed.
- Unverified until the first CI run: that `nc -z` exists in the pinned rclone image for the readiness probe (the fixture falls back to a short sleep), the `up -d --wait --wait-timeout` behaviour with two projects, volume permissions for `/app/data/backup` written by `ops run` containers, and the whole real-container chain. On failure, the wrapper output (scrubbed of generated secrets) is in the assertion message of the first test.

## Notes for the user

- First use on a host: `sudo deploy/backup.sh --install-timer` (needs the `trading` user in the docker group, which bootstrap does) and, once on an EMPTY bucket, `deploy/backup.sh --init-remote`.
- Restore onto a fresh host: bootstrap, put the same `BACKUP_*` values (including the `rclone obscure`d crypt passwords) into `.env`, then `deploy/restore.sh` (or `--no-start` to inspect first).
- Update: `deploy/update.sh --ref v0.3.1`; back out with `deploy/update.sh --rollback`. A database migration applied by the newer version is not undone; restore from a backup if the old code cannot read it.
- Windows: git warns LF will become CRLF for the new files, same as earlier plans (`.gitattributes` forces LF for deploy files).
