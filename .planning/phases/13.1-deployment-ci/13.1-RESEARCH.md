### Locked Decisions

**CI pipeline**
- **D-01:** One new workflow `.github/workflows/ci.yml` on `push` and `pull_request` to master with parallel jobs: `test` (pytest), `lint` (ruff check + ruff format --check), `types` (mypy). The existing `registry-gate.yml` and `research-gate.yml` stay as they are and are referenced, not merged. All jobs use `uv sync --frozen --extra dev` on Python 3.13.
- **D-02:** Actions and tool versions are pinned (`astral-sh/setup-uv` with an exact uv version instead of `latest`; the existing `paper_freeze_check.yml` `version: "latest"` is tightened in the same change). CI must not need Binance, Telegram or a database secret; tests that need PostgreSQL use a `postgres:17-bookworm` service container or are marked and skipped with an explicit reason.
- **D-03:** Add a `docker` CI job that builds the image from a clean checkout and runs `docker compose config`, the shell-script lint and the local cutover test (D-15). Image push to a registry is out of scope (no registry decision yet).
- **D-04:** If mypy or ruff are not green today, the first plan fixes or narrowly scopes them (per-module overrides with a written reason) so the gate is real. No `|| true`, no `continue-on-error`.

**Image and Compose hardening**
- **D-05:** Pin by exact tag plus digest: `ghcr.io/astral-sh/uv:<exact version>`, `python:3.13.<patch>-slim-bookworm`, `postgres:17.<minor>-bookworm`. Digests are recorded in the Dockerfile/compose and a short doc table with the refresh procedure (a deliberate, reviewed bump, never automatic).
- **D-06:** HEALTHCHECK uses the venv interpreter (`/app/.venv/bin/python -m src.data.collector --healthcheck`), not `python` on PATH (F-705). Healthchecks are per service, because the paper and live processes need their own probes.
- **D-07:** PostgreSQL publishes only `127.0.0.1:${POSTGRES_PORT}:5432` (F-709). Data lives only in named volumes (pgdata, rawdata, backupdata, plus a logs volume); no bind mounts of host data.
- **D-08:** One Compose file with services `postgres`, `collector`, and profile-gated `paper` and `live` (profiles `paper`, `live`; `live` never starts by default). The same image serves all of them with different commands. Services without a runnable entrypoint yet (paper and live composition arrive in Phases 16 and 24) are declared as documented placeholders, not invented commands.
- **D-09:** Secrets come only from `env_file` (`.env`, mode 0600, gitignored). `DATABASE_URL` is built inside compose from the required vars. Error text and logs are scrubbed: a small redaction helper (structlog processor plus exception-message scrubber) masks the values of known secret env vars and API-key shaped strings (F-708). A test proves a secret planted in an exception never reaches log output. Paper and test credentials use separate variable names from live (OPS-06).

**Bootstrap**
- **D-10:** `deploy/bootstrap.sh` is idempotent bash, targets Ubuntu 22.04/24.04 and Debian 12, and takes `--dry-run`. It does: apt update, Docker Engine + compose plugin from Docker's apt repo, a non-root `trading` user in the docker group, key-only SSH (`PasswordAuthentication no`, `PermitRootLogin no`, written as a drop-in under `sshd_config.d` and validated with `sshd -t` before reload), `ufw` allowing only SSH (default deny incoming), chrony enabled with a drift check, repo checkout at a given ref, and `.env` created from a secrets file path argument with mode 0600. It uses no provider-specific service.
- **D-11:** Bootstrap refuses to disable password SSH unless an `authorized_keys` entry exists for the target user (anti lock-out). It prints a final checklist of operator steps it cannot do (Binance IP whitelist, heartbeat monitor).

**Backups**
- **D-12:** Backups go to an S3-compatible store through `rclone` (provider-neutral: AWS S3, Backblaze B2, Wasabi, MinIO) with `rclone crypt` for client-side encryption, configured from env vars, run by a separate backup container or a host systemd timer. The bundle format and manifest stay the existing `src/ops/backup.py` bundle (pg_dump + Parquet + sha256 manifest), extended, not replaced. Retention: 7 daily, 4 weekly, 6 monthly, enforced by the existing prune logic and verified by a test with a fake clock. The backup key is stored off-VPS; losing it is documented as unrecoverable.
- **D-13:** `deploy/backup.sh`, `deploy/restore.sh` and `deploy/backup-drill.sh` are Linux shell wrappers that defer all logic to `python -m src.ops.backup`, like `scripts/backup-drill.ps1` (kept for Windows). `restore.sh` restores the latest verified bundle onto an empty host and refuses a bundle whose manifest hashes do not match. The drill is tested locally against a MinIO container.

**Provider-portable migration**
- **D-14:** `deploy/migrate.sh <old> <new>` follows the roadmap order exactly: rsync pre-sync while old runs, stop old collector, final rsync + `pg_dump`, restore on new, start the collector from its watermark, print a coverage report. The script never shuts down the old host; a human does that after the report is clean. The coverage report reuses `src/data/coverage.py`; the recorded gap across the switch is reported in minutes and fails above a configurable threshold (default 60 minutes). Supports `--dry-run`.
- **D-15:** The cutover test runs two Docker environments locally (two Compose projects, distinct volumes and ports, rsync over ssh on a container network) and asserts: no Parquet file lost (set equality of paths and sha256), no watermark row lost, gap bounded and reported. Marked `@pytest.mark.docker`, run in the CI `docker` job and locally; skipped with a clear reason when Docker is absent.

**Runbook and documentation**
- **D-16:** The runbook covers bootstrap, update (git pull, build, `up -d`, rollback to the previous image digest), migrate and restore, in `docs/operations/RUNBOOK.md` (extend, do not fork). It states which steps were tested locally and which need a real host. A DECISIONS row (D050) records these choices, with same-change witnesses in DOC_STATUS and SECURITY_AND_OPERATIONS.

## Summary

The phase is mostly assembly of well-understood tools, but verification this session found **sixteen concrete defects or premise problems** in the current repo and in CONTEXT that the plans must absorb (full list in "Findings that change the plan"). The most consequential: MinIO container images no longer exist on Docker Hub (so the D-13 "local MinIO" test must use something else; `rclone serve s3` was verified to work and needs no extra image); the existing `prune_bundle` is a stale-source garbage collector, not a retention policy, so the 7/4/6 retention is new code; the existing production `pg_dump` path cannot work inside the compose stack (no PG client in the image, a libpq-invalid `postgresql+psycopg://` URL, and a Debian-12 client would be v15 against a v17 server); and the named-volume mount points under `/app/data` come up root-owned and unwritable by the non-root app user (reproduced).

CI is cheaper than feared: the full suite is green locally (2387 passed, 7 skipped, about 6 min on this Windows box), mypy has only 3 trivial errors in `src`, ruff check has 30 findings (22 auto-fixable after format) and `ruff format --check` flags 150 files (reflow only; AST-identical apart from one docstring). Two backfill CLI tests failed intermittently under heavy local load and passed on every sequential re-run, so treat them as load-sensitive, not as formatting casualties.

The testing approach for the shell side is pytest + subprocess with stubbed binaries on PATH and a `--dry-run` plan printer (the repo already does this for the research-gate step, including the Windows `bash` discovery trick), plus shellcheck in CI. The cutover and drill tests run against real containers (`docker` marker), skip cleanly without a reachable daemon, and are the only place the rsync/ssh/pg_restore/rclone path is exercised end to end.

**Primary recommendation:** Keep all new logic in typed Python modules under `src/ops/` (`backup` extensions, `cutover`, `redaction`), keep `deploy/*.sh` as thin LF-only wrappers with a shared `--dry-run` runner, pin every image by `tag@sha256`, fix ruff/mypy first (plan 1) so the CI gate is real from its first commit, and treat the first Linux CI run as the real validation of the suite (it has never run on Linux in full).

## Findings that change the plan

Each item was verified by running something this session unless tagged otherwise.

1. **MinIO images are gone (D-13 premise).** `hub.docker.com/v2/repositories/minio/minio/tags` returns `{"message":"object not found"}` [VERIFIED: Docker Hub API 2026-10-01]; the community edition stopped publishing images in Oct 2025 and the repo is archived [CITED: itsfoss.com/news/minio-moves-away-from-open-source, vonng.com/en/db/silo-is-coming]. **Use `rclone serve s3` as the local S3 double** (verified below). Keep "S3-compatible (AWS, B2, Wasabi, Other)" in docs; drop MinIO from tests.
2. **Retention is not implemented anywhere (D-12 premise).** `prune_bundle` is documented as "Reconcile the bundle against the live source roots (WR-04). Deletes bundle entries under `parquet/<basename>/...` whose source file no longer exists" (src/ops/backup.py:249-251). There is no date-based retention, no snapshot naming, no remote. 7/4/6 is a new pure function plus a remote delete step.
3. **`_prod_pg_dump_runner` cannot work in the compose stack.** (a) The app image has no `pg_dump` (Dockerfile installs nothing via apt). (b) It passes `os.environ["DATABASE_URL"]` straight to `pg_dump` (`subprocess.run([pg_bin, "--format=custom", "-f", str(out), db_url], check=True)`, backup.py:473-476) while compose sets `postgresql+psycopg://...`; libpq rejects that scheme: `psycopg.conninfo.conninfo_to_dict("postgresql+psycopg://u:p@h:5432/db")` raised `ProgrammingError missing "=" after "postgresql+psycopg://u:p@h:5432/db" in connection info string` [VERIFIED: ran in project venv]. **That error text contains the password** (a real F-708 leak and the best test fixture for the redaction test). (c) Debian bookworm ships PG client 15; `pg_dump` refuses a newer server, so a PGDG `postgresql-client-17` is required [CITED: postgresql.org/download/linux/debian; version-mismatch refusal is documented pg_dump behaviour, ASSUMED unverified here].
4. **Named volumes under `/app/data` are root-owned and unwritable by `appuser` (reproduced).** Dockerfile:27 is `RUN useradd -m appuser && mkdir -p /app/data && chown -R appuser /app` and compose mounts `rawdata:/app/data/raw` and `backupdata:/app/data/backup`. Built an equivalent Alpine test image: with only `/app/data` pre-created the mount point was `drwxr-xr-x root root` and `touch` failed `Permission denied`; with `/app/data/raw` pre-created and chowned before the mount the same command succeeded [VERIFIED: docker run this session]. The image must `mkdir -p /app/data/raw /app/data/backup /app/logs` and chown them (fixed numeric UID) so the volume inherits ownership on first use.
5. **Compose bugs that bite D-15.** (a) In-network URL uses the host-published port: `@postgres:${POSTGRES_PORT:-5432}/${POSTGRES_DB:-trading}` (docker-compose.yml:46); with `POSTGRES_PORT=5433` (needed for two environments) the collector would dial `postgres:5433`, which does not exist inside the network. Use literal `5432` in-network. (b) `container_name: trading-alert-postgres` / `trading-alert-app` (compose:12, :33) make two projects on one daemon collide; remove `container_name`. A top-level `name:` plus `-p` override works [VERIFIED: `docker compose -p other config` printed `name: other`].
6. **`${VAR:?msg}` is interpolated even for profile-disabled services.** Verified: a service with `profiles: ["ops"]` and `${NEEDED_FOR_B:?...}` made plain `docker compose config` fail [VERIFIED]. Therefore backup/live variables must use `${VAR:-}` in compose and be validated fail-closed inside the container entrypoint (Python), keeping `:?` only for always-on `postgres` vars.
7. **`env_file: .env` must exist at `compose config` time** [VERIFIED: error "env file ...\.env not found"]; `--env-file .env.example` fixes interpolation only. CI must `cp .env.example .env` before `docker compose config`. Never run `docker compose config` with real secrets in CI logs (it prints resolved env).
8. **Lint/type gates are not green.** `ruff check`: 30 errors (9 UP017, 6 F841, 5 E501, 5 F401, 3 I001, 1 B017, 1 E402). `ruff format --check`: 150 files would be reformatted (mostly `tests/`). `mypy src`: 3 errors. Tests are green. Details and the verified fix path are in "Gate repair".
9. **CRLF hazard.** `git config core.autocrlf` is `true` here and `git ls-files --eol` shows `i/lf w/crlf` for `Dockerfile`, `docker-compose.yml` and all workflows. A CRLF `deploy/*.sh` fails with `bad interpreter` on Linux. `.gitattributes` currently has only `tests/fixtures/phase10/render_golden/* -text` (read this session). Add `eol=lf` rules and a test that scans for `\r` in `deploy/`.
10. **HEALTHCHECK and CMD defects.** Dockerfile:36 is `CMD python -m src.data.collector --healthcheck || exit 1`: bare `python` is the base-image interpreter that has none of the venv packages (sqlalchemy, polars...), so the probe cannot work (F-705). `CMD ["uv", "run", "python", "-m", "src.data.collector"]` (Dockerfile:38, compose:57) makes the runtime re-resolve through uv (cache dir, possible network sync); use `/app/.venv/bin/python` directly. Also `uv:latest` (Dockerfile:4).
11. **Alembic is never run by the stack.** No code path in `src/data/collector.py` creates tables (the only DB bootstrap is `scripts/dev/migrate.ps1`, a Windows helper). A fresh VPS needs `alembic upgrade head`; model it as a one-shot `db-upgrade` compose service the collector depends on (`service_completed_successfully`). `src/db/alembic/env.py` reads `DATABASE_URL` and `alembic.ini` calls `fileConfig`-style logging, which can reset logger configuration in that process (apply redaction setup after, or accept it for the one-shot).
12. **sshd drop-in ordering.** sshd uses "the first obtained value" per keyword and `Include` globs are "processed in lexical order" [CITED: manpages.ubuntu.com sshd_config]. Cloud images ship `50-cloud-init.conf` (often `PasswordAuthentication yes`); a `99-` file would lose. Name the drop-in `00-trading-hardening.conf`, and prove the result with `sshd -T` (effective config), not only `sshd -t`. `KbdInteractiveAuthentication` defaults to `yes` [CITED: same page], so with PAM it can still allow password logins; set it to `no` too.
13. **rclone crypt facts (verified with rclone 1.75.1).** Env-var-only config works (`RCLONE_CONFIG_<NAME>_TYPE=crypt`, `_REMOTE`, `_PASSWORD`, `_PASSWORD2`). Passwords **must be obscured** (`rclone obscure`); an unobscured value fails with `failed to decrypt password: base64 decode failed when revealing password - is it obscured?`. A **wrong key is silent at the root**: `rclone lsf -R BAD:` printed only `NOTICE: Skipping undecryptable dir name` and exited 0; sub-path operations exit 3 "directory not found". Restore/retention must treat "no snapshots found" as an error, not as an empty store. `obscure` is reversible (not encryption): the real secret is the raw passphrase kept off the VPS.
14. **Docker operational hygiene missing from compose:** no log rotation (json-file default is unbounded on a 24/7 VPS), no `init: true` (Python as PID 1 does not get default SIGTERM handling, so `docker stop` waits 10 s then SIGKILLs [ASSUMED standard Docker behaviour]), no `stop_grace_period`, no `.dockerignore` (only `.dockerignore`-less builds; `ls` shows none).
15. **httpx logs full URLs at INFO and Telegram URLs embed the bot token** (`https://api.telegram.org/bot<TOKEN>/...`); the standard fix is `logging.getLogger("httpx").setLevel(logging.WARNING)` [CITED: python-telegram-bot issue #3743 and many downstream fixes]. The redaction design must cover stdlib logging, not only structlog.
16. **Docker on this dev box:** CLI present (29.5.3), daemon was down at first and came up later; registry pulls run at roughly 30-100 KB/s and a container could not reach `files.pythonhosted.org` (`uv sync` inside `docker build` failed with `client error (Connect)`). So a full `docker build` and large pulls cannot be validated locally here; they are validated in the CI `docker` job. Local `docker` tests must skip when the daemon is unreachable and should prefer small, already-pulled images.

### Pattern 1: Dockerfile with two targets, venv interpreter, pre-owned mount points

**What:** `runtime` target runs collector/paper/live; `ops` extends it with pg client 17, rclone, rsync, ssh client. Pin everything; never run uv at runtime; create and chown every volume mount point before `USER`.
**When to use:** all services. The existing test `tests/test_collect_list.py::test_dockerfile_copies_universe_directory` requires the line `COPY docs/research/universe ./docs/research/universe` to occur **exactly once** and **before the first line that starts with `RUN useradd`** (test_collect_list.py:378-384). Keep a line beginning `RUN useradd` and do not repeat the COPY in the `ops` stage.
**Example (illustrative design; image digests are the verified values above, other names are proposals):**

### Pattern 3: Bash scripts as testable thin wrappers

`deploy/lib.sh` provides `run()` (prints `+ cmd` in `--dry-run`, executes otherwise), `die()`, `require_cmd()`, and every script ends with `if [[ "${BASH_SOURCE[0]}" == "$0" ]]; then main "$@"; fi` so tests can `source` and call single functions with stubs first on `PATH`. OS detection reads `${OS_RELEASE_FILE:-/etc/os-release}` so tests can feed Ubuntu 22.04/24.04, Debian 12 and a rejected release. Mutations (apt, systemctl, ufw, sshd, usermod) are all behind `run`.

### Pattern 4: pytest + subprocess for bash on Windows

Reuse `_find_bash()` from `tests/test_research_gate_negative.py`: it rejects `C:\Windows\System32\bash.exe` (the WSL launcher) and falls back to `Program Files\Git\bin\bash.exe`; module-level `pytest.skip` when absent. Write script fixtures with `newline="\n"`. Set `MSYS_NO_PATHCONV=1` when passing `/container/paths` through Git Bash to `docker` (otherwise `/t` became `T:/` in this session). Move `_find_bash` into a shared test helper.

### Anti-Patterns to Avoid

- `uv run ...` as the container command/HEALTHCHECK (re-resolves, needs cache and maybe network).
- `${VAR:?}` on profile-gated services (breaks `docker compose up` for everyone).
- A `99-` sshd drop-in (loses to `50-cloud-init.conf`); verify with `sshd -T`.
- Treating an empty `rclone lsf` as "no backups yet" during restore.
- Passing a SQLAlchemy URL to libpq tools; passing a password on argv (use `PGPASSWORD`/`PGPASSFILE` and strip `+driver`).
- `rsync --delete` anywhere in cutover (the raw store is append-only; deletion can only lose data).
- `docker compose config` with real secrets in CI logs.
- Letting scripts decide shutdown of the old host (D-14: human decides).

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Client-side encryption of backups | Own AES/age wrapper | `rclone crypt` (D-12) | Authenticated NaCl secretbox, name encryption, `cryptcheck`; verified working over S3 |
| S3 client / multipart / retries | boto3 or hand-written SigV4 | rclone S3 backend | Provider-neutral (AWS, Wasabi, `Other`), env-var config, already pinned |
| Local S3 for tests | Custom fake S3 | `rclone serve s3 --auth-key` | Verified: crypt-over-S3 copy, list, purge, restore all passed |
| Incremental host-to-host file sync | Python copy loop | `rsync -a --ignore-existing` over ssh | Files are immutable (`os.replace` + no-overwrite), resumable, standard |
| Gap detection across the switch | New gap math | `src.data.coverage.gap_ranges_for_files` | Single definition of a gap (D-19) already tested; takes `step_ms`, `max_step_ms` |
| File hashing / manifest | New hasher | `src.ops.backup._sha256_file` / `write_manifest` (promote to public helper) | One contract for backup, restore and cutover fingerprint |
| Log redaction of exceptions | Regex in each caller | One `Redactor` used by processor, excepthooks, stdlib filter, and explicit `scrub()` for prints | The leak surface is wide (structlog, stdlib, uncaught, print) |
| Time sync | Custom NTP check daemon | chrony + `chronyc tracking` parse | OS-native; collector already warns on > 1000 ms offset |
| Cron-like scheduling | Own scheduler | systemd timer (`Persistent=true`) | Catches missed runs after reboot |
| YAML parsing in tests | PyYAML dependency | `docker compose config --format json` + `json` | Avoids a SUS-flagged new dependency |
| Retention date maths | Ad-hoc string slicing | One pure function over parsed UTC timestamps | Deterministic, property-testable |

**Key insight:** every piece here has a mature tool; the failure modes are in the seams (URL schemes, ownership of mount points, interpolation timing, ordering of config precedence, silent wrong-key listings). Test the seams, not the tools.

**Recommended remote layout inside the crypt remote** (Parquet is immutable and append-only per D-04; copying it every night as a new snapshot would multiply storage and request counts by the retention depth):

```
<bucket>/                    (crypt: names and contents encrypted)
  snapshots/<YYYYMMDDTHHMMSSZ>/pg.dump
  snapshots/<YYYYMMDDTHHMMSSZ>/manifest.json   # lists pg.dump + every parquet path and sha256 at that time
  parquet/<root basename>/...                  # rclone copy only, never delete, never sync
```

Restore of snapshot S: pull `snapshots/S`, pull exactly the Parquet files named in S's manifest from `parquet/`, rebuild the local bundle, `verify_bundle`, then restore. Retention deletes only `snapshots/*` (a few MB-GB each); Parquet is never pruned (document growth; research data is irreplaceable, RUNBOOK section 11). This keeps "the existing bundle format and manifest, extended" while avoiding N full copies. If the planner prefers literal full-bundle snapshots, cost is storage times 17 and many small objects; flag it (Open Question 1).

**Retention function (pure, no clock needed):** given snapshot ids parsed as UTC datetimes, keep: newest snapshot per UTC day for the 7 most recent days that have a snapshot; newest per ISO week for the 4 most recent such weeks; newest per calendar month for the 6 most recent such months; union is kept, everything else is deleted; unparseable names are never touched; always at least the newest snapshot. Counting "most recent periods that have a snapshot" (not "periods before `now`") means a silent backup outage never ages out the last good backups. The D-12 "fake clock" test then drives snapshot creation with an injected `now_utc` over 400 simulated days, applies retention after each, and compares to an independent brute-force oracle. Delete only **after** the new snapshot's upload and `rclone cryptcheck` succeeded.

**rclone adapter contract:** all config from env (compose maps `BACKUP_S3_*` to `RCLONE_CONFIG_BACKUPS3_*`; crypt remote `BACKUPS3CRYPT` wraps `BACKUPS3:<bucket>`); run with a subprocess runner injected like `PgDumpRunner` so unit tests use a fake and one integration test uses the real binary against the `local` backend; treat exit code 3 and an empty root listing as errors; use `rclone cryptcheck` after upload (hashes are not stored for crypt, `check` is wrong [CITED: rclone.org/crypt]).

**Data model facts (read this session):** watermark table `collector_watermarks(symbol PK, data_class PK, last_tick_utc, updated_at_utc)` (src/db/models.py:108-113); gap journal `collector_gaps` (:135-142). Parquet layout `<root>/data_class=oi/symbol=<sym>/date=<YYYY-MM-DD>/tick-<iso>.parquet`, `data_class=oi_research`, and `data_class=funding/.../sweep-<iso>.parquet` (collector.py:220-295). Cadence `COLLECTOR_CADENCE_SECONDS = 300.0`; funding health bound `9 * 3600.0`; `TICK_GAP_FACTOR = 2` (coverage.py:50). `gap_ranges_for_files(files, *, series, symbol, interval, time_column, step_ms, start_utc, end_utc, max_step_ms=None) -> list[GapRange]` (coverage.py:344-355).

**What "gap across the switch" means.** OI snapshots are point-in-time and cannot be re-fetched later (that is why the collector is time-sensitive, F-107), so the downtime window is a real hole in the `oi` series. Funding is resumed from its watermark by `async_funding_sweep`, so a funding hole is recoverable. For a hole between observations P and N, time without data is `N - P`; with `GapRange(start=P+step, end=N)` that is `(end - start + step)` ms. Report per symbol in minutes and fail above `--max-gap-minutes` (default 60).

**Proposed `src/ops/cutover.py` (strict typed, importing `src.data.coverage` and `src.db.models`):**
- `fingerprint(raw_root) -> dict[relpath, sha256]` (skip `.*.tmp`), JSON output; run on both sides inside the app/ops image, compare as sets (paths + hashes), not byte counts.
- `watermark_snapshot(database_url) -> dict[(symbol, data_class), last_tick_utc]`.
- `report(old_fp, new_fp, old_wm, new_wm, raw_root, window, max_gap_minutes)`: missing/extra/mismatched files, watermark rows lost or regressed, per-symbol OI gap minutes via `gap_ranges_for_files(... time_column="observed_at_utc", step_ms=300_000, max_step_ms=TICK_GAP_FACTOR*300_000 ...)` over `[min(old last_tick) - 2 cadences, floor(now)]`, plus `build_oi_coverage` rows as context. A trailing hole (no tick yet on the new host) is a gap, which naturally forces "wait for the first new tick".
- Exit codes: 0 clean; 1 data loss (file/watermark); 3 gap above threshold; 2 usage.

**Order in `migrate.sh` (new host runs it, pull model):** 1 preflight (ssh reachability, image present on both, `--dry-run` prints the plan) -> 2 pre-sync `rsync -a --ignore-existing --exclude '.*.tmp'` while old runs -> 3 stop old collector (`init: true` + `stop_grace_period` make this clean) -> 4 final rsync, then `pg_dump` on old (quiescent, so order between them is free) and `fingerprint`/`watermark_snapshot` on old -> 5 restore on new (postgres only, `pg_restore`, `db-upgrade`) -> 6 `up -d collector` -> 7 wait for the first new tick, then `cutover report`. Never `--delete`, never touch the old host's power.

**How rsync reaches data inside named volumes (D-07 forbids bind mounts):** on a real host the `trading` user is in the docker group but cannot read `/var/lib/docker/volumes`. Use rsync's `--rsync-path` to run the remote side in the ops image: `--rsync-path="docker run --rm -i --entrypoint rsync -v trading_rawdata:/data:ro trading-alert-ops:<tag>"` and the source `old:/data/raw/`; the receiving side runs the rsync client in an ops container mounting the new `rawdata` volume plus the ssh key (read-only) and `known_hosts` (strict host key checking). This is [ASSUMED] technique (documented rsync option, not executed here); the local test uses plain `rsync` against an sshd+rsync sidecar that mounts the old volume, so the docker-run form is verified only on a real host (say so in the runbook). It requires the OLD host to have the ops image, i.e. the old host must be updated to Phase 13.1 first; state this prerequisite.

## Redaction design (D-09, F-708)

**Where:** `src/ops/redaction.py` (stdlib + structlog typing only; `src/ops` already hosts `backup.py` which imports structlog). **No new dependency.** Wire at each entrypoint `main()` (collector, backup, cutover, coverage/backfill CLIs) via one `configure_logging()`.

**Components**
1. `Redactor.from_environ(environ)`: collect values of env vars whose NAME matches `PASSWORD|SECRET|TOKEN|API_KEY|ACCESS_KEY|CRYPT|PRIVATE` (plus `DATABASE_URL*` password part), minimum length 8, add percent-encoded and JSON-escaped variants, sort longest first, compile one alternation with `re.escape`.
2. Shape patterns (do not depend on env): URL userinfo `://user:pass@`, Telegram token `\d{8,10}:[A-Za-z0-9_-]{35}`, `signature=<64 hex>`, `X-MBX-APIKEY` header values (64 alnum), AWS-style access key ids, PEM private key blocks. Mask to `[REDACTED]`.
3. Key-name rule in the structlog processor: any event key whose lowercased name contains `password`, `secret`, `token`, `api_key`, `authorization`, `signature` has its value replaced regardless of content.
4. `redact_processor` recursive over str/dict/list/tuple; **must run after `structlog.processors.format_exc_info`** so traceback text (the usual leak) is a plain string by then, and before the renderer. Use `JSONRenderer` for containers. Do not use `dict_tracebacks` with locals and do not use `ConsoleRenderer`'s pretty exceptions in production: both can render local variable values; structlog docs also state pretty exceptions require `format_exc_info` to be absent [CITED: /hynek/structlog console-output docs].
5. `install_global_hooks(redactor)`: wrap `sys.excepthook` and `threading.excepthook` (uncaught exceptions bypass structlog), add a `logging.Filter` on root handlers that scrubs `record.msg`/`record.args`, set `httpx` and `httpcore` loggers to WARNING (token-in-URL), and expose `scrub(text)` for the few `print(..., file=sys.stderr)` sites that format exceptions (`collector-health: UNKNOWN - {type}: {exc}`, `collector: {exc}`).
6. `alembic` calls `fileConfig` and can reset handlers in that process: call `install_global_hooks` after, or accept that the one-shot `db-upgrade` logs only alembic/sqlalchemy INFO.

**Test (D-09 requirement, plus F-708 reality):** plant `SECRET=` a random hex in env, raise `RuntimeError(f'missing "=" after "postgresql+psycopg://trading:{SECRET}@postgres:5432/trading" in connection info string')` (the verified libpq error shape), call `log.exception`, capture stdout; assert `SECRET not in output` and `[REDACTED]` in output. Add: key-name rule with a short value; stdlib `logging.getLogger('x').error('%s', SECRET)`; httpx URL containing a Telegram-shaped token; uncaught exception in a subprocess (`python -c` after `install_global_hooks`) with stderr scrubbed; negative control (non-secret text untouched); an AST/grep test that `.env.example` contains no value matching the shape patterns.


Procedure: (1) refuse unless `[ -s ~trading/.ssh/authorized_keys ]` and `ssh-keygen -l -f` accepts at least one line (D-11); (2) write drop-in to a temp file; `sshd -t -f` on the full config; (3) install atomically; (4) `sshd -T` and assert `passwordauthentication no`, `kbdinteractiveauthentication no`, `permitrootlogin no` in the effective output, else remove the drop-in and abort; (5) `systemctl reload ssh` (service is `ssh` on Debian/Ubuntu; on Ubuntu 24.04 socket activation exists, use `try-reload-or-restart`); keep the current session open and tell the operator to open a second session before closing. `Include /etc/ssh/sshd_config.d/*.conf` is at the top of the stock files on these releases ([ASSUMED] for 22.04/Debian 12 specifics; verify in the plan by reading the stock file and failing if the Include is absent).

`.env` creation: `umask 077; install -m 0600 -o trading -g trading "$SECRETS_FILE" /opt/trading/.env`, then verify `stat -c %a` equals `600`, required keys present and non-empty without echoing values, and refuse placeholders (`change_me`). ## Common Pitfalls

### Pitfall 1: Root-owned named volumes
**What goes wrong:** collector dies with `PermissionError` on first write to `/app/data/raw`.
**Why:** mount point not present in the image, so the runtime creates it root-owned; reproduced.
**How to avoid:** pre-create and chown mount dirs in the image with a fixed UID; docker-marked test that runs `touch /app/data/raw/x` as the image user against fresh volumes.
**Warning signs:** `Permission denied` in `docker logs`, healthcheck `no-watermark` forever.

### Pitfall 2: `:?` required-variable on gated services
**What goes wrong:** every `docker compose` command fails for operators who have not configured backup/live.
**How to avoid:** `${VAR:-}` + Python-side fail-closed validation; compose test runs `config` with only the base vars.

### Pitfall 3: Internal DB port vs published port
**What goes wrong:** `POSTGRES_PORT=5433` breaks the collector's URL.
**How to avoid:** literal `5432` in-network; a compose test sets a non-default `POSTGRES_PORT` and asserts the URL.

### Pitfall 4: sshd precedence and PAM keyboard-interactive
**What goes wrong:** password login still works after "hardening".
**How to avoid:** `00-` drop-in, `KbdInteractiveAuthentication no`, assert on `sshd -T`.

### Pitfall 5: Self lock-out
**What goes wrong:** key-only SSH enabled with no working key for the target user.
**How to avoid:** D-11 guard before writing the drop-in; ufw SSH rule before `enable`; keep the current session open; dry-run prints the plan.

### Pitfall 6: Wrong crypt key looks like an empty bucket
**What goes wrong:** restore or retention concludes "no backups" and deletes or skips.
**How to avoid:** non-empty-listing assertion; a sentinel object (known file) decrypted and compared during every push and drill; exit code 3 treated as failure.

### Pitfall 7: Unobscured crypt password in env
**What goes wrong:** rclone refuses to start (`is it obscured?`). Operators paste the raw passphrase.
**How to avoid:** `.env.example` comment and a startup check in the backup entrypoint: attempt `rclone obscure --reveal`-free validation by listing the sentinel; document `rclone obscure` and that the raw passphrase lives off-VPS.

### Pitfall 8: pg_dump/pg_restore plumbing
**What goes wrong:** SQLAlchemy URL passed to libpq (error echoes the password), client 15 vs server 17, password on argv, watermark ahead of files if order reversed.
**How to avoid:** normalise URL, `PGPASSWORD` env, `postgresql-client-17` in `ops`, pg_dump strictly before the Parquet snapshot, test the runner builds the argv/env as expected using a fake `subprocess` seam.

### Pitfall 9: First Linux run of the full suite
**What goes wrong:** CI is the first time the entire suite runs on Linux (registry-gate runs only a subset). Windows-only assumptions (case-insensitive paths, line endings, `PermissionError` retries in `atomic_write_parquet`, PowerShell-skip tests) may fail.
**How to avoid:** make the first plan's last task "push to a branch and fix forward until green", a non-autonomous checkpoint (the repo is private, `gh` is not installed here, so the real run cannot be observed from this machine). I attempted a WSL Ubuntu run but its network could not fetch uv, so this is unverified [ASSUMED].

### Pitfall 10: CRLF in shell scripts, Dockerfile COPY'd text, systemd units
**How to avoid:** `.gitattributes` `eol=lf` for `deploy/**`, `*.sh`, `*.service`, `*.timer`, `Dockerfile`, `*.yml`; test that no file under `deploy/` contains `\r`.

### Pitfall 11: Git Bash path mangling and `bash.exe` (WSL launcher) on Windows
**How to avoid:** `_find_bash()` pattern; `MSYS_NO_PATHCONV=1` for docker commands with Unix paths; skip tests when bash is absent.

### Pitfall 12: Docker daemon absent, slow, or without egress on the dev box
**How to avoid:** docker-marked tests skip with an explicit reason when `docker info` fails; CI `docker` job is the authority; keep local fixtures small and pre-pull-friendly; never make the default `pytest` run depend on Docker.

### Pitfall 13: Healthcheck cold start
**What goes wrong:** on a fresh DB there is no watermark until the first tick (up to 5 min), so the probe reports unhealthy early.
**How to avoid:** `--start-period=6m`; nothing depends on `service_healthy` of the collector; Docker does not restart unhealthy containers, so this is informational only.

### Pitfall 14: Unbounded container logs and PID-1 signals
**How to avoid:** `logging:` options on every service, `init: true`, `stop_grace_period`.

### Pitfall 15: `docker compose config` leaking secrets, `.env` in build context
**How to avoid:** CI uses `.env.example` copies only; `.dockerignore` excludes `.env*` (except `.env.example`), `.git`, `.venv`, `data`, `logs`, `.planning`, `.gsd`, `.omo`, `.codegraph`, caches, `__pycache__`, `tests`.

### Pitfall 16: Unrecoverable or silent data decisions in cutover
**What goes wrong:** treating OI gap as recoverable, or shutting down the old host automatically.
**How to avoid:** the report says OI gap minutes are permanent loss; funding is recoverable; script never powers off the old host.

### Retention oracle sketch (illustrative)

```python
def select_retained(names, *, keep_daily=7, keep_weekly=4, keep_monthly=6):
    parsed = sorted((parse_utc(n), n) for n in names if is_snapshot(n))  # ascending
    keep = set()
    for key_fn, count in (
        (lambda d: d.date(), keep_daily),
        (lambda d: d.isocalendar()[:2], keep_weekly),
        (lambda d: (d.year, d.month), keep_monthly),
    ):
        newest_per_bucket = {}
        for dt, n in parsed:
            newest_per_bucket[key_fn(dt)] = n  # later overwrites earlier => newest
        buckets = sorted(newest_per_bucket)[-count:]
        keep.update(newest_per_bucket[b] for b in buckets)
    return keep, {n for _, n in parsed} - keep
```

### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Secret in logs or exception text (libpq error echoing URL; httpx URL with bot token) | Information disclosure | One `Redactor` across structlog, stdlib, excepthooks; httpx WARNING; test with the real libpq error shape |
| Secret baked into image or build context | Information disclosure | `.dockerignore`, `.env` only via runtime `env_file`, CI uses `.env.example` |
| Compromised or curious object store | Information disclosure | Client-side crypt incl. names; provider sees ciphertext |
| Backup rollback or deletion by a bucket-write attacker | Tampering / DoS | crypt gives confidentiality and per-file integrity, not freshness; recommend provider versioning/Object Lock (operator) and manifest sha256 verification; document |
| Tampered bundle at restore | Tampering | `verify_bundle` before any destructive step; refuse mismatch |
| Password SSH or root login | Spoofing / Elevation | drop-in + `sshd -T` assertion; fail2ban not required for key-only |
| Self lock-out | Denial of service (self) | D-11 guard, ufw allow before enable, second session |
| Exposed Postgres | Information disclosure / Tampering | publish `127.0.0.1` only; ufw is not the control for Docker ports |
| Docker group = root | Elevation | accept for a single-operator host, document; no docker socket mounted into containers |
| Supply chain: floating tags, unpinned actions | Tampering | tag@digest, SHA-pinned actions, `uv sync --frozen`, `uv lock --check`; shellcheck-py and PyYAML not added |
| Wrong crypt key mistaken for empty store | Denial of service | sentinel decrypt check, exit-3 handling |
| Clock drift | Tampering with timestamps | chrony + drift check; collector warns > 1000 ms |
