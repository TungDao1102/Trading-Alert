GitHub Actions facts the plan relies on (official pages read 2026-10-07/08, summarised by a fetch tool, not verified live; 16-RESEARCH.md S1 and 16-RESEARCH-GAPS-RESULT.md G15/G16): scheduled workflows run only on the default branch (`master`) at its latest commit; the schedule "can be delayed during periods of high loads ... the start of every hour ... some queued jobs may be dropped"; no numeric delay bound and no retry of dropped runs is documented; a scheduled run is identified by `github.event_name == 'schedule'` and `github.event.schedule` (the cron string); `workflow_dispatch` runs must never count as scheduled ticks; caches unused for over 7 days are removed; run records and artifacts are kept 90 days by default (1-400 for private repositories). A run that did not happen writes no line, so a missing tick is detected outside the workflow (plan 16-15 reconciler) and recorded as EVIDENCE_GAP, never CLEAN (REV-02, REV-18). Moving the cron off the top of the hour is a candidate mitigation only (G15; REV-18 allows it provided it changes no semantics, creates no tolerance and is not treated as proven). This plan does not change the cron and treats nothing as proven: the cron minute is the user's checkpoint Q-Q in plan 16-30 (L-01 fixes the cadence, hourly, not the minute; keeping `0 * * * *` here was a planner convenience, not a user decision), plan 16-47 sets the recorded line, and until then this plan only asserts the line that is on master today and that it has the hourly form the reconciler of plan 16-15 accepts. Under either answer a missing tick is an EVIDENCE_GAP; no mitigation relaxes the rule.
