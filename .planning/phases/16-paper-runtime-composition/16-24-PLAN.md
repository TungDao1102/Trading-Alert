<objective>
Build the runtime's per-closed-bar pipeline: the stateful glue between the supervisor's tagged bars (plan 16-08) and the typed tick seam (plan 16-10). It owns the incremental state D-02 gives the runtime (engine-window buffers, dedup of seen open times, the epoch pinned once at start), applies the closed-bar and source-tag rules (D-05, D-06, L-11), writes the heartbeat row per processed closed bar that coverage needs (D-07), and emits the live decision-surface record (D-20: "the paper loop emits it from live bars"). REST-backfilled klines enter the same path as live ones (inherited G2-007).

Conflict surfaced for the user (research Q-D): L-11 forbids signals for bars that closed while the process was DOWN; a WebSocket drop with the process still up is not "down", and CONTEXT does not say whether bars recovered by REST in that case may be evaluated. Task 2 is a blocking-human decision. Until then the tracer only exercises LIVE_WS and REST_WARMUP, whose rules are locked.

Purpose: SC1 needs a composed chain whose evaluated bars are exactly the closed live bars, with every processed bar on record so restarts (plan 16-29), coverage (plan 16-15) and the trial evaluator (plan 16-25) can prove "no duplicate signal, no missing journal row, no fabricated bar" (L-04).
Output: `src/paper/pipeline.py`, tests, the Q-D record.
</objective>
