<objective>
Make restarts and downtime explainable and safe (D-02: per-restart warm-up from REST before the first evaluated bar; D-04: state restored from the soak database; D-06: a bar closed while the process was down is a gap and never a signal; L-04: "after every restart warm-up completes before the first evaluated bar, with no duplicate signal and no missing journal row"; L-11; REV-01: every gap has a reason code and PLANNED_RESTART is its own code, still uncovered). Research Pitfall P8: an empty last-close map after a restart hides the downtime gap and breaks dedup.

Purpose: SC1 "runnable as a process" includes surviving restarts on the soak host; the evaluator (plan 16-25) fails the trial on any duplicate signal, missing row or late bar, so the runtime must make them impossible by construction.
Output: `src/paper/restart.py`, runtime wiring, unit and PG tests.
</objective>
