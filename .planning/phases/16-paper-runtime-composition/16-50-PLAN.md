<objective>
Off-host heartbeat sender for the collector. The user chose healthchecks.io on 2026-10-09 as the external off-host monitor of D042 condition 1 ("thêm healthchecks.io vào plan"); RUNBOOK 11.4 and 19.3 still say the repository sends no heartbeat. This plan builds the sender so the collector on the EC2 host is watched as soon as it runs there: `deploy/heartbeat.sh` plus a systemd service and timer pair under `deploy/systemd/`, in the style of `deploy/backup.sh` and `trading-backup.*` (lib.sh helpers, `parse_args` flags, `--dry-run`).

Purpose: a stopped or wedged collector must silence the signal, so the monitor alerts the operator (acceptance condition `HEARTBEAT_MONITOR_ALERT_RECEIVED`, RUNBOOK 19.3), and the sender can never make an outage worse (the collector's Open Interest minutes lost to a stop are permanent, RUNBOOK 15.4, L-14).
Output: the script, two unit templates, offline tests, a validator guard, corrected RUNBOOK and guide text, SOURCES rows, and the decision record line.

Planner choices recorded (Claude's discretion; none is a monitor value):
- Secret handling: the ping URL lives in a root-only file (default path `/etc/trading/heartbeat.url`, mode 0600) and reaches the service through systemd `LoadCredential`, so the unprivileged `trading` account that runs docker reads a private copy. It is not an `.env` variable: `.env` is handed to every container by `env_file`, the redaction layer matches secret variable names (a name like a ping URL matches none of them), and `.env` parsing in bash is fragile. `deploy/heartbeat.sh --set-url` stores the URL from standard input without echo, so it never enters shell history or argv.
- Success ping by default; a fail ping is opt-in (`--fail-ping`, baked into the unit by `--install-timer --fail-ping`) because a fail ping alerts at once and bypasses the grace period, which is the operator's O-12 value (L-08, L-09). Silence after a failed probe is already an alert once period plus grace elapse.
- The timer pairs `OnBootSec` and `OnUnitActiveSec` with the same operator interval and sets neither `Persistent` nor a randomized delay: a catch-up ping after downtime would mask the very outage the monitor exists to report. `AccuracySec` is a structural systemd setting (the default coalesces timers by up to a minute), not a monitor value.
- The only code default is the per-step transport bound (probe and ping), because a oneshot unit has no start timeout by default and a hung `docker` or `curl` would otherwise freeze the timer. It is read from `HEARTBEAT_STEP_TIMEOUT_SECONDS`, copied from the collector's probe timeout in `docker-compose.yml` (project convention, the way plan 16-32 copies the collector probe values), and carries the provenance label PLACEHOLDER in the script comment: not a monitor value, never tuned.
- "Heartbeat" here means the external ping. It is unrelated to the paper runtime's per-bar heartbeat records (coverage evidence of plans 16-15, 16-16, 16-24); RUNBOOK 11.9 says so.
- Scope boundary: this sender probes the collector only. The paper and live process probes, and the external monitor's coverage of every long-running process required by Phase 24 criterion 4, belong to Phase 24; nothing in this plan changes the paper service probe of plan 16-26.
- Ordering: the dependency on plan 16-20 is the user's instruction. Plan 16-20 runs its own `HEARTBEAT_MONITOR_ALERT_RECEIVED` row before this sender exists; the operator verification below repeats that row with this sender.
</objective>
