<objective>
Close plan 16-29 deviation 1 (16-29-SUMMARY.md, "Epoch check is epoch-scoped"): `check_epoch_consistency` compares the pin file only with the EPOCH_PINNED record of the same epoch, because `RuntimeStatePort` reads by epoch id. A newer pin of a different epoch in the soak database is not detected, so a restart could resume a trial whose pin has been superseded. A new port query `latest_epoch_pins()` (in-memory and PostgreSQL) makes the check cross-epoch: the pin a restart trusts is the latest across all epochs (REV-18, L-04 "single epoch").

Wave 8, not 7: plan 16-51 (wave 7) also edits `src/paper/runtime_state.py`, and same-wave plans must not share a file. 16-52 uses nothing 16-51 builds, so `depends_on` stays [16-29]; the wave alone orders the two edits.

Consequence for the soak (stated for plans 16-40 and 16-43): any EPOCH_PINNED recorded on the soak database after the trial pin, for example by a rehearsal, makes every restart of the trial refuse with exit 6. That is the intended fail-closed behaviour; the 16-43 clean-state check (zero EPOCH_PINNED before the pin) already keeps rehearsal pins off the trial.
