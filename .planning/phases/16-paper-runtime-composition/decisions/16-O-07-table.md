# O-07 table: healthy-feed and timing numbers for the paper soak (plan 16-27)

Prepared 2026-10-10. The user value column is empty on purpose. This table proposes no value anywhere: the code values are what the code holds today (not ratified), the facts are quoted with their source, and the observations are measurements from one live smoke, not thresholds.

These numbers define HEALTHY for the paper soak only. They are not LIVE safety thresholds; Phase 20 owns T-06 and G2-026.

The continuous_uncovered_ceiling_seconds row is mandatory (REV-17: 95 percent of 336 h still allows about 16.8 h uncovered).

A missing freeze tick is an EVIDENCE_GAP and restarts the trial (REV-18); freeze_tick_grace_seconds only separates a late tick from a missing one.

## How to read the columns

- **where it lives**: a configuration key (written into `config/paper/paper-runtime-v1.toml` by plan 16-34 from the user's answer) or `file:line` of a code constant, as read on 2026-10-10.
- **current code value**: what the code holds now. None of these is ratified (O-07). A new value for a code constant inside the paper tick or the supervisor moves pinned digests, so the plan records the request and stops (see the end of this file).
- **facts**: Binance or GitHub facts with URL and read date. Source for all of them: `16-RESEARCH-GAPS-RESULT.md` (G1, G2, G3, G15), read 2026-10-08, labelled "not verified live".
- **observation**: measured in the live smoke of plan 16-21 (`evidence/16-21-ws-smoke-live.json`, proof_class REAL_SMOKE, BTCUSDT, 1m/1h/4h, 2026-10-10 09:09:35Z to 13:19:38Z, 15000 s, public data, no credentials). Labelled "observation, not a threshold".
- **user value**: empty. Filled only with the user's words (decision record `16-DEC-O-07.md`).

## Smoke caveat that applies to every observation row

The host clock was behind Binance during the smoke: `clock_skew_ms` ran from 182 ms (start) to 580 ms (end), where positive means the host clock is behind and the figure includes request latency. Arrival latency is receipt time on that host clock minus the bar close time, so a behind clock produces negative latencies and 165 `future_close_events` (bars whose close time lay after the host clock at receipt). Read every latency below together with that skew. The smoke ran one symbol, one network path and one 4.2 h window; it saw no real bar-close outage ("no bar closed during the outage" for the forced drop).
