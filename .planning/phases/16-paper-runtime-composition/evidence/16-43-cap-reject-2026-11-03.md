## Sizing versus cap (the numbers that do not agree)

- Cap per the parameter set `research-run-1-a01`: `cluster_cap = 0.005`, applied as a rate
  times equity (`src/risk/portfolio.py`, `resolve` in the parameter-set helper).
- Sizing log, 2026-11-03 06:00 (`risk.quantize`): `realized_risk` 2.99357 and 2.99877 USDT. The
  allowed risk back-computed from `realized_to_allowed_ratio` is 3.00 = 0.005 x 600. So sizing used
  600, not the current equity.
- Cap at current equity: 0.005 x 592.61 = 2.963 USDT. A candidate at 2.99877 exceeds it with zero
  open positions. The cluster check fails whenever the candidate's risk is above the cap.
- Earlier passes fit the same rule: 2026-10-28 02:00 cap 0.005 x 598.17 = 2.991 against 2.9867
  (passed); 2026-10-29 02:00 cap 0.005 x 596.33 = 2.982 against 2.9427 (passed).
- A standard 0.5% candidate passes only when equity is at least 2.99877 / 0.005 = 599.75 USDT.

Working hypothesis, not yet confirmed in code: sizing uses a fixed 600 while the cluster cap uses
equity at the UTC day start, so the cap falls below the sized risk once equity drops below about
599.75. The hypothesis is consistent with every pass and rejection listed above. Which equity the
sizing path reads was not traced in code.
