# 16-43 — paper market-stream silence and restart loop, 2026-10-27

Record of one incident in the soak (trading-soak-paper-1), kept as trial evidence. All times UTC
unless stated (the operator's local time is UTC+7).

## What happened

- First watchdog warning `paper runtime: market stream silent` at 00:06:25 (silent 133 s).
- The ten kline streams (1h and 4h for BTC, ETH, BNB, SOL, XRP) stayed silent. The runtime
  rebuilt the connections (`paper_ws.rebuilt`, 3 connections before and after) and the streams
  stayed silent.
- `paper runtime failed closed (exit 7)`, reason: market stream silent after the bounded recovery
  (B1-CR-01, 16-DEC-WS-WATCHDOG). Seven cycles, each about 4 minutes:

| Fail-closed (exit 7) | Container start (Docker) |
|---|---|
| 00:11:25 | 00:11:26 |
| 00:15:43 | 00:15:47 |
| 00:20:04 | 00:20:08 |
| 00:24:24 | 00:24:28 |
| 00:28:44 | 00:28:47 |
| 00:33:05 | 00:33:07 |
| 00:37:25 | 00:37:29 |

- The last start (00:37:29) led to a healthy runtime (`runtime start` 00:37:34). No silence or
  fail-closed line appears after 00:37:25 in the container log.
- Healthcheck was `healthy` at 14:11–14:16 (`FailingStreak` 0).
- Docker `RestartCount` for the container: 7.
- The paper heartbeat stopped during the loop, so healthchecks.io reported DOWN and then UP about
  30 minutes later (operator observation).

Since 2026-10-26 00:00 the container log holds 22 `market stream silent` lines and 7
`failed closed` lines. Before 00:11 on 2026-10-27 there was no fail-closed exit in that log.

## Checks made

| Check | Result |
|---|---|
| Host kernel log (`journalctl -k`, `dmesg`) for 00:00–00:40 | Only Docker veth events, matching the container restarts. No NIC link down, reset or ENA message. |
| EC2 instance status (`describe-instance-status`) | Instance status `ok`, system status `ok`, no scheduled event. |
| Collector container log from 00:00 | No line matching websocket, reconnect, silent, closed, error or timeout. This does not show whether the collector received kline messages, because the collector logs no message-level events there. |
| `collector_gaps` with `expected_utc` ≥ 2026-10-27 00:00 | 0 rows. The table records missing closed bars. No 1h or 4h bar close falls between 00:04 and 00:37, so this check cannot show a stream gap in that window. |
| `collector_watermarks` | Only `funding` and `oi` rows (REST data). Latest `oi` update 14:25:00; latest `funding` 08:00 and 12:00. The table keeps one row per key, with no history, and it does not cover kline streams. Not usable for this window. |
| Paper log at the SDK level | `No WebSocket connections available for unsubscription` appears when the watchdog fires, while the runtime still counts 3 connections. This suggests the SDK connection state and the runtime state disagree. Not yet confirmed as the cause. |
| Telegram | `NetworkError` at 14:05:53 (`paper.shadow.telegram_error`) and a transient reply failure at 14:12:43. Not part of the silence, but a second network symptom the same morning. |

## Not established

- Whether Binance stopped sending kline messages during 00:04–00:37, or the paper connection
  stopped receiving them. The collector evidence above does not decide this.
- The root cause of the connection-state mismatch in the SDK layer.

## Effect on the trial

- The paper runtime was not running for about 33 minutes (00:04–00:37 silence, with restarts).
  `continuous_uncovered_ceiling_seconds = 900` in `config/paper/paper-runtime-v2.toml` may be
  exceeded. The evaluator (`scripts/evaluate_trial_soak.py`) decides this from the exported bundle;
  this record does not change any threshold.
- No order was placed; the runtime is SHADOW only.
