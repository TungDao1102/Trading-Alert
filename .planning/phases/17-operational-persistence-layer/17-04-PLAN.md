<objective>
Make every journal id builder the audit flagged (F-412) deterministic and collision-free, so the PostgreSQL journal store (plan 08) can use the primary key as its idempotency key: a replay writes the same id, a different event never collides.

Purpose: D-10 and research C7. Today SAFE_MODE, sweeper and drill ids are (name, millisecond) and collide for different events at the same instant; callback ids embed a random suffix per delivery, so a Telegram redelivery writes a second receipt.
Output: correlated_event_id, fixed builders in four modules, tests.

## Decisions applied in this plan

- C7 (orchestrator resolution): callback correlation ids come from Telegram `callback_query.id`; journal ids are pure functions with fixed step labels; no DB-derived sequence.
- Non-correlated events (SAFE_MODE, sweeper, drills) keep using the existing content_hash_event_id (it already hashes event type, entity, occurred_at and payload).
- Callback payloads drop the wall-clock receipt field; the event's occurred_at_utc column keeps the delivery time. Plan 08's journal store compares identity fields and payload on a primary-key conflict and ignores occurred_at_utc/created_at_utc, so a redelivery is a no-op and a genuinely different event under one id is a JournalConflict.
