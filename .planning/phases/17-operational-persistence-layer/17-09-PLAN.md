<objective>
Make approval decisions durable and DB-enforced: a PostgreSQL approval store behind the existing callables, an explicit consumption state on the domain Approval, and a replay layer that cannot return the wrong approval after a lost race.

Purpose: APRV-02 durability (F-404), D-06/D-16/D-17, research C13, C15, C16.
Output: domain and mapper change, replay.py change, src/persistence/approvals.py, tests.

## Decisions applied in this plan

- C8/C13: Approval gains consumption_status (default UNCONSUMED) and consumed_at_utc (default None); CONSUMED requires status APPROVED and a UTC consumed_at_utc. Only the execution-state consume transaction (plan 01) sets them; this store never consumes.
- C15: typed ApprovalAlreadyDecided in src/approval/replay.py.
- C16: short-id mapping is insert-then-verify; a mismatched (signal_id, trade_plan_id) for an existing short id fails closed (matches 0003's "re-plans fail closed instead of silently rebinding").
- Pitfall 13: one approval row per action; "APPROVE decided, then a pending SKIP row for the same plan tries to decide" must be rejected by the database.
- record_short_id_mapping exists because dispatch_callback looks the mapping up before any decision (the Phase 23 sender writes it at send time; plan 14 uses it to seed the end-to-end test).
