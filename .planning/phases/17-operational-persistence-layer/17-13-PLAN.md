<objective>
Persist the remaining durable state the phase owns: the per-plan constraint snapshot (EXEC-04) and SAFE_MODE / enablement / kill-gate state (D-22), with rehydration that survives a restart.

Purpose: EXEC-04 persistence and revalidation; F-606 restart-rehydrate gap; research C14 (controllers could not start in a non-default state).
Output: two stores, controller state snapshot and rehydrate constructors, three test modules.

## Decisions applied in this plan

- Snapshots are write-once evidence: record with ON CONFLICT (trade_plan_id) DO NOTHING plus sha comparison (RowConflict on a different snapshot for the same plan); the append-only trigger from plan 02 forbids updates.
- System state: per-key monotonically increasing state_version computed as latest + 1 inside the transaction; a concurrent append for the same key loses on uq_system_state_events_key_version and raises RowConflict (the caller re-reads); state_event_id is content_hash_event_id over (key, version, state JSON, recorded time); the journal event has event_type SYSTEM_STATE_CHANGED, entity_type SystemState, entity_id the key, correlation_id "system_state:<key>".
- State dict formats (owned by the controllers): SAFE_MODE {"in_safe_mode": bool, "entered_at_utc": ISO string or null, "entered_reason": string or null}; LIVE_ENABLEMENT {"disabled": bool, "enabled_at_utc": ISO string or null, "operator_id": string or null}; KILL_GATE {"kill_gate_state": KillGateState value}.
- The kill-gate state has no controller in this phase; latest(KILL_GATE) is validated against KillGateState by the store's typed reader.
