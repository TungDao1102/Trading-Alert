<objective>
Lead with one production-quality vertical slice of EXEC-05: a user-data `ORDER_TRADE_UPDATE` frame becomes a typed, frozen, SDK-free event, then a `FillEvent`, then a `FoldedPositionView` through the existing idempotent `fold_fills` (D-06, F-104). Then stop at the design-review gate for the event types that Phases 19, 20 and 24 will import (D-01, costly to reverse), and only afterwards write the remaining strict parsers (ALGO_UPDATE with `rm`, ACCOUNT_UPDATE deltas, listenKeyExpired, the anomaly paths of D-05).

Purpose: the stream is a hint plus evidence; REST stays the authority (D-05). The parsers therefore never coerce: anything that does not validate becomes a `StreamAnomaly` that the router (plan 18-15) journals and surfaces as a divergence.
Output: the events module, the algo-status vocabulary, the `FillEvent` commission extension (G3-009), synthetic fixtures labelled SYNTHETIC_FROM_SDK_MODEL, reusable AST guards, and the design decision record.

Machine rule: no network. Frames are synthetic, built from the field set of the installed SDK models (read as files, never executed against Binance); real RECORDED_DEMO frames replace or complement them in plan 18-21.
</objective>
