<objective>
Give the first callers of the Binance user-data stream the persistence they need, and nothing more: every move of an Order or a Position out of UNKNOWN records its evidence source in the append-only journal in the same transaction (G4-034), the Order's `exchange_status` and `exchange_order_id` get their store methods with the lookups a stream router needs (G4-043), and stream anomalies get a deterministic journal event builder (D-05, D-08). No new table.

Purpose: AGENTS.md exchange authority - state out of UNKNOWN requires Binance evidence (D051 item i). The transitions module states that recording the evidence source was deferred to Phase 18 and 20 "when the first callers exist"; the router of plan 18-15 is the first caller.
Output: `src/domain/stream_records.py`, the evidence gate and new methods in `src/persistence/entities.py`, PostgreSQL tests.

Out of scope: wiring these into a running process (Phases 20 and 24), equity or position truth from ACCOUNT_UPDATE (Phases 20 to 22), the other Phase 17 review info items in `execution_state.py`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stream or REST evidence -> Order and Position state | A state taken out of UNKNOWN changes what the system believes about money at risk |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-18-20 | Tampering | an Order or Position leaving UNKNOWN by local inference (timeout, operator guess) | high | mitigate | transition_order and transition_position raise EvidenceRequired without an ExitEvidence; evidence is journaled in the same transaction; evidence on any other transition is a ValueError |
| T-18-21 | Repudiation | the evidence source (REST reconcile or user-data event) not recorded, so an audit cannot tell why a state changed | medium | mitigate | UNKNOWN_EXIT_EVIDENCE journal event with source, reference, observation time and deterministic id; rollback if the append fails |
| T-18-22 | Tampering | exchange_status or exchange_order_id overwritten with a conflicting value, or a terminal local state reopened | high | mitigate | RowConflict on a different non-null exchange id; local_status is never touched by update_order_exchange_state; the database terminal trigger still blocks terminal local_status changes (tested) |
| T-18-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed or changed in this plan |
</threat_model>
