Lead with the not-found slice (F-501, F-205): a query by client id answers "absent" only for the taxonomy category ORDER_ABSENT of a QUERY call, proven against the SDK error objects and with the old legacy-message test reversed on purpose. Then route the cancel path (F-502, F-503) and the rate-limit behavior (F-506) through the taxonomy, prove placement is called exactly once for every error class, and add an AST guard so the message-text fallbacks cannot return.

A wrong "absent" enables a duplicate order; a wrong retry floods the exchange or extends a ban.
Output: the rewired `src/adapters/binance_usdm.py` and three test files.

Out of scope: `recvWindow` on signed calls (plan 18-13), retries of query calls (queries stay single-attempt: the user's record allows cancel and read retries only within the existing bounded retry, and reads have no adapter retry today; the SDK's own bounded GET retry is governed by the ratified `client.sdk_retries`), the manager's SAFE_MODE reaction (unchanged), any gate on REST calls after a 429 other than the bounded cancel retry (the record blocks REST only for a 418).
</objective>
