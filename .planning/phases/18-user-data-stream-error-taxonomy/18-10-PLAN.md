<objective>
Lead with the not-found slice (F-501, F-205): a query by client id answers "absent" only for the taxonomy category ORDER_ABSENT of a QUERY call, proven against the SDK error objects and with the old legacy-message test reversed on purpose. Then route the cancel path (F-502, F-503) and the rate-limit behavior (F-506) through the taxonomy, prove placement is called exactly once for every error class, and add an AST guard so the message-text fallbacks cannot return.

Purpose: today `_is_order_not_found_error` falls back to the text of any exception, `_cancel_retry_predicate` retries nearly everything (including -2019 and auth errors), and `_is_already_canceled_message` treats the text "-2011" anywhere as success (08-REVIEW IN-10). A wrong "absent" enables a duplicate order; a wrong retry floods the exchange or extends a ban.
Output: the rewired `src/adapters/binance_usdm.py` and three test files.

Out of scope: `recvWindow` on signed calls (plan 18-13), retries of query calls (queries stay single-attempt; the SDK's own bounded GET retry is governed by the ratified `client.sdk_retries`), the manager's SAFE_MODE reaction (unchanged).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Binance error answer -> adapter decision | The decision to treat an order as absent, to retry, or to wait changes whether a duplicate order or a ban can occur |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-18-25 | Tampering | a placement retried after an ambiguous failure, or an order mapped to absent from message text, producing a duplicate entry | critical | mitigate | Placement makes exactly one SDK call for every error class (matrix test); absence only from ORDER_ABSENT of QUERY or CANCEL; unknown codes raise; AST guard keeps message fallbacks and placement loops out |
| T-18-26 | Denial of service | retrying during an IP ban (HTTP 418) extends the ban up to days | high | mitigate | 418 is never retry-eligible; with a policy the adapter refuses calls until retry_after (or the policy wait) elapsed, sending no request; 429 waits retry_after |
| T-18-27 | Tampering | cancel retried on a definitive rejection, an authentication error or an unknown error, hiding the failure and burning requests | medium | mitigate | retry_eligible allows only RATE_LIMITED and STATUS_UNKNOWN on cancel, bounded by the existing ceilings; matrix test over the categories |
| T-18-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed or changed in this plan |
</threat_model>
