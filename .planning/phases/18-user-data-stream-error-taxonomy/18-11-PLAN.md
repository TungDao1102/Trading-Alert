<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Binance WebSocket -> raw SDK callback -> adapter queue | Untrusted frames enter the process here; the callback runs on the event loop thread inside the SDK |
| listenKey (credential) -> logs and exceptions | The key grants read access to the account's order, position and balance stream |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-18-28 | Information disclosure | listenKey or account data (balances, positions) written to logs by the SDK's root-logger INFO lines or by project code | high | mitigate | register_runtime_secret on receipt; no f-string or exception carries the key; idempotent SdkNoiseGuard rejects the SDK's "Received message" and "Subscribing to streams" records; redaction test with an SDK-style line |
| T-18-29 | Tampering | the SDK route silently delivering nothing (a bare-listenKey SUBSCRIBE not accepted, or an envelope the SDK cannot route), so the project believes it has a live view | high | mitigate | The adapter makes no liveness claim; plan 18-18 makes event delivery through this route its first acceptance criterion; plan 18-19 is the gated direct fallback; the supervisor goes UNKNOWN on any gap and REST remains the authority |
| T-18-30 | Denial of service | an exception in the SDK callback (swallowed and re-emitted as a connection error) or an unbounded queue causing a rebuild storm or memory growth | medium | mitigate | The raw callback never raises; the queue is bounded by a ratified limit; overflow sets a flag and counts losses; connection error handling is the supervisor's, based on the connection list |
| T-18-31 | Tampering | stale names in the SDK's module-global stream map making a re-subscribe a silent no-op after an unsolicited close | high | mitigate | rebuild removes exactly the old listenKey name and creates a fresh client; contract tests pin the SDK behaviors this relies on; isolation fixture in every behavioral test |
| T-18-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed or changed in this plan |
