<objective>
Build the SDK-backed operations that the Demo probe (plans 18-17 and 18-23) needs and that `BinanceUsdmAdapter` deliberately lacks (explicit-quantity reduce-only conditional legs, market orders, cancel-all, user trades, account balance, raw not-found answers), behind one project-owned adapter whose results are data, so that an exchange error is an observation to record and not an exception to handle. The probe is the first and only runner of this code on a connected machine, so correctness of every SDK call is pinned offline against the installed method signatures.

Purpose: D-15 and D-16 ask the probe to record "the exact (class, code, message)" of each case; `BinanceUsdmAdapter` maps not-found to `found=False` and hides the code. D055 and G2-029 need order shapes the production adapter never sends.
Output: `src/adapters/binance_probe.py`, adapter tests, an SDK signature contract test.

Out of scope: running anything against Binance, the case order and the evidence file (plan 18-17), the production adapter (unchanged).
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-18-32 | Elevation of privilege | the probe adapter sending orders to mainnet or with a mainnet client | critical | mitigate | The adapter never builds a client or selects an environment; it receives a client built by build_sdk_client; the probe script asserts the environment before every call and refuses any other (plan 18-17); a dry run never reaches this class |

| T-18-35 | Tampering | a mistyped SDK keyword or enum discovered only during the first live run, leaving orders open | medium | mitigate | Contract test binds every call's kwargs to the installed method signatures and validates enum members offline |
| T-18-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed or changed in this plan |
