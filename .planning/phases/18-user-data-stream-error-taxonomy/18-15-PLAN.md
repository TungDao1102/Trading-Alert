<objective>
Close the offline loop of EXEC-05: a router turns the supervisor's trusted events into the project's outcomes - `FillEvent`s for `fold_fills`, status hints with `USER_DATA_EVENT` evidence, algo-status hints with the ratified class, account deltas, journaled stream anomalies and divergence records for the reconciler (D-05 to D-08) - and a replay rig proves the position view is identical for a stream replayed, reordered and duplicated (D-21).

Purpose: "the stream feeds fold_fills and reconciliation, REST is the fallback". The router never decides state; unknown, malformed or surprising events are evidence for the reconciler, not input to a guess. It is a library with fake-driven tests (D-04): it imports nothing from persistence and is wired by Phases 20 and 24.
Output: `src/adapters/binance_userdata_router.py`, sink fakes, the rig, the router tests and the replay tests.

Out of scope: reconcile loop logic, SAFE_MODE rules and the mapping of `StreamDivergence` onto the reconciler's closed divergence vocabulary (Phase 20), equity or daily-loss use of commission (Phase 21), wiring into a process.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-18-43 | Tampering | stream used as the only source of truth: fabricated state for an unknown order, or a missed fill unnoticed | critical | mitigate | Unknown orders and algos create no state, only an anomaly and a divergence; the z-total check detects a missed TRADE and calls the REST fills fallback; REST snapshots remain the authority (supervisor baseline) |
| T-18-44 | Tampering | duplicate, replayed or reordered fills double-counted, or a REST-synthetic fill mixed with stream fills | high | mitigate | Idempotent (order id, trade id) key in the unchanged fold_fills; permutation and replay tests; the mixed key-space case is a pinned negative control and the REST fallback uses real trade ids |
| T-18-77 | Tampering | the documented double ALGO_UPDATE of a trailing stop (ia false then ia true) counted as two lifecycle updates, doubling divergences or diagnostics for one stop | medium | mitigate | Lifecycle key without is_activated and event times; the second event is counted, not routed; a status change is never suppressed; five named tests |
| T-18-45 | Information disclosure | rm free text, payload data or a listenKey journaled | medium | mitigate | rm is scrubbed and capped; anomaly records carry hashes and field names, never raw payloads; the listenKey is not in any event type; test with a key-bearing frame |
| T-18-46 | Repudiation | an anomaly or sink failure silently lost | medium | mitigate | Every anomaly is journaled with a deterministic id; a failing sink is recorded as a ROUTER_SINK_FAILURE record; a failing journal re-raises |
| T-18-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed or changed in this plan |
</threat_model>
