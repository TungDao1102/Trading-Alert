<objective>
Build the connected-machine smoke for the user-data stream and its offline dry run (D-04, D-15, D-18): start the stream on Demo through the project's adapter and supervisor, place and cancel one far LIMIT order, prove typed `ORDER_TRADE_UPDATE` events arrive through the SDK `user_data` route, keep the listenKey alive, force a transport drop and watch UNKNOWN to snapshot to LIVE, record what `DELETE` then `PUT` returns, and write one scrubbed evidence file. The dry run drives the identical pipeline over fakes so CI and the executor can prove the tool before a human runs it.

Purpose: plan 18-18 (blocking-human) runs this tool on Demo; its first acceptance criterion is delivery through the SDK route because that is the one structural unknown of the phase. A shared operator-evidence module (atomic scrubbed JSON, confirmation phrase, owner-approved order limits) is reused by the probe script of plan 18-17.
Output: `src/ops/operator_evidence.py`, `scripts/user_data_smoke.py`, four test files.

Out of scope: running anything against Binance, the probe cases (plan 18-17), the direct-transport option (plan 18-19 adds `--transport direct`), any process composition beyond this script.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator shell -> Binance Demo (signed order, listenKey) | The tool places and cancels a real Demo order and holds the account's listenKey |
| evidence and fixture files -> repository | Anything written is committed and must be free of secrets and listenKeys |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-18-47 | Elevation of privilege | the smoke reaching mainnet or running with a live key | critical | mitigate | No host, key, secret or LIVE option; environment choices DEMO and TESTNET only; build_sdk_client plus assert_environment before every stage; refuse when LIVE credential variables exist; execute needs a terminal and the exact phrase; AST scan for the mainnet host and for .env reads |
| T-18-48 | Information disclosure | key, secret, signature or listenKey in evidence, fixtures or captured logs | high | mitigate | Scrub before and re-scan after an atomic write; the listenKey is registered with the redactor; the log scan (acceptance g) and the evidence scan; raw frames written through the same scrub |
| T-18-49 | Tampering | the dry run reaching a mutating method or the network | high | mitigate | The dry run builds only fakes; tests patch sockets, HTTP and sleep to fail; proof_class FAKE can never be mistaken for REAL_SMOKE by the verdict functions |
| T-18-50 | Tampering | an order left open or a position left behind after the smoke | medium | mitigate | One far order only, cancelled in a finally path; account state before and after; MANUAL_CLEANUP_REQUIRED recorded and exit 1 when the end state is not flat |
| T-18-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed or changed in this plan |
</threat_model>
