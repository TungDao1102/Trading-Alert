Prepared 2026-10-16. The table is presented with the user value column empty and proposes no value.

These numbers are SAFETY thresholds for the Binance client and the user-data stream (D061 items H and I). They are not paper-soak health numbers and not trading parameters; Phase 20 owns the reconcile cadence and the WebSocket-silence threshold (T-06, G2-026).

Every Binance documentation fact below is "not verified live". Plan 18-01 tried to re-read every page on 2026-10-16 and each request ended in an AWS WAF challenge, so every row of `docs/SOURCES.md` section "Facts read for Phase 18 (research 2026-10-15; executor re-read dated per row)" is UNVERIFIED for the re-read; the facts quoted here are the research baseline (`18-RESEARCH.md`, fetch log rows B1 to B13, WebFetch or search summaries of 2026-10-15, not character-exact). The connected-machine smoke (plan 18-18) repeats the reads. SDK defaults were read on 2026-10-16 as plain files from the project virtual environment (`binance_common` 4.4.0, `binance-sdk-derivatives-trading-usds-futures` 17.4.0); nothing was executed. Project code values were read on 2026-10-16 in this worktree (branch `phase-18`); none of them is ratified for the purpose of this table.

## How to read the columns

- **key**: the canonical key, written `section.key` (26 keys; plans 18-02, 18-07 and 18-09 use exactly these names).
- **unit**: ms, seconds, count, messages, or true/false. "or none" marks the three nullable keys.
- **meaning**: what the number controls.
- **where it lives**: the section of `config/binance/binance-limits-v1.toml` (written only by plan 18-09 from the user's record `18-DEC-O-18-01.md`) and the required, default-free field that receives it: `ClientLimits` (`src/adapters/binance_client.py`, plan 18-04, exists now), `SignedCallPolicy` and `RateLimitPolicy`, `DriftLimits` and `ClockDriftGuard`, `StreamLimits` (`src/adapters/binance_limits.py`, plan 18-07), and the plan that consumes it.
- **documented limit or SDK default (source)**: a Binance fact with its SOURCES.md row and research row id (always "not verified live"), or an SDK default with its file and line.
- **project precedent (file, value read 2026-10-16)**: an existing project constant or a Phase 16 O-07 record that concerns a similar quantity. A precedent is context, not a default.
- **observation**: a measurement, labelled "observation, not a threshold". The only measured input available is the Phase 16 live smoke (`.planning/phases/16-paper-runtime-composition/evidence/16-21-ws-smoke-live.json`, proof_class REAL_SMOKE, public market streams only, no credentials, 2026-10-10, one host, one 4.2 h window). No user-data stream has been run by the project.
- **options and trade-offs**: the shapes the value can take and what each side costs. Listed neutrally; nothing is recommended.
- **user value**: empty. Filled only with the user's words (decision record `18-DEC-O-18-01.md`).

## Observation caveat that applies to every drift and reconnect row

`clock_skew_ms` in the Phase 16 smoke is defined there as "Binance server time minus the injected clock at the call, milliseconds; positive means the host clock is behind; includes the request latency". It read 182 at the start and 580 at the end (status OK). The host was therefore behind Binance during the whole smoke and the figure includes request latency; no separate round-trip time was recorded. The smoke's forced transport drop recovered in about 2.3 s (WS_DISCONNECT to WS_RECONNECT) and about 2.8 s (to resumed data), with 9 SDK reconnect events under a 3600 s rotation override. All of this concerns the public market streams, not `/private`.

## Section C: the four flagged ALGO_UPDATE status rows (D-07, research F3)

Allowed classes (CONTEXT D-07): ACTIVE, TERMINAL_OK, TERMINAL_FAILED, UNKNOWN. A fifth class (for example a separate in-transit class) would amend CONTEXT D-07; such an answer is recorded as CODE CHANGE REQUESTED and stops plan 18-02 (planned separately with `/gsd-plan-phase 18 --gaps`). The D055 invariant holds in every case: a position is never treated as healthy until Binance has confirmed the protective stop, and a successful API call that placed a stop is not evidence of protection.

Source of the meanings: the event page itself is UNVERIFIED (research B5; SOURCES row Event-Algo-Order-Update, executor re-read 2026-10-16 also failed); the meanings are the research search summary B5a (2026-10-15) and `09-EXCHANGE-FACTS.md` Fact 2 (transcription of an archived copy of 2026-01-13), which agree. Not verified live. The REST `algoStatus` vocabulary is not enumerated on the REST pages (research B10) and its equality with the WebSocket `X` vocabulary is ASSUMED (research A3).

| status | documented meaning | allowed classes | judgment the research flagged | user value |
|---|---|---|---|---|
| TRIGGERING | The triggering condition is met and the order is forwarded to the matching engine. | ACTIVE, TERMINAL_OK, TERMINAL_FAILED, UNKNOWN | In transit: neither confirmed protection nor failed. | |
| TRIGGERED | The order is placed into the matching engine. | ACTIVE, TERMINAL_OK, TERMINAL_FAILED, UNKNOWN | In transit: neither confirmed protection nor failed; the child order identity is not established until the probe captures it (research P14). | |
| FINISHED | The triggered order was filled or canceled in the matching engine. | ACTIVE, TERMINAL_OK, TERMINAL_FAILED, UNKNOWN | Lifecycle-complete, not "protection executed": EXECUTION_SPEC 6.1 says FINISHED does not mean filled; the position must be read from the exchange. | |
| CANCELED | The conditional order was canceled. | ACTIVE, TERMINAL_OK, TERMINAL_FAILED, UNKNOWN | OK when the project canceled it and a failure when it did not; the origin of the cancel is not in the event, so the reconciler's position-based check stays the arbiter. | |

The other three documented statuses have no judgment flagged and are implemented as stated unless the user writes a different class in the record (this restates D-07 and the documented meanings; it is not a new choice):

- NEW (placed into the Algo Service, not yet triggered): implemented as ACTIVE.
- REJECTED (denied by the matching engine, for example a margin check failure): implemented as TERMINAL_FAILED.
- EXPIRED (canceled by the system, for example a GTE_GTC conditional order after all positions were closed): implemented as TERMINAL_FAILED.
- Any other value, an empty string or a missing value: UNKNOWN (fail closed, D-07); not a choice.
