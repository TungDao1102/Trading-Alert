<objective>
Build the tracer of the single protection model of D-10 (owner-adopted direction in 19-NOTES.md, "adopt kèm các điểm trên"): a fill-driven protection coordinator that, on the first positive fill of a resting entry, places the closePosition stop and cancels the entry remainder at the same time, then confirms both over REST. This plan delivers the happy path (branch B0), REST-only fill detection, the account-wide "no new entry while unprotected" gate and the router wiring; the failure branches and deadlines are plan 19-14, the TP legs plan 19-16, the manager hand-off plan 19-15.

Purpose: nothing in src drives protection from a fill today (research summary, F11). The coordinator is step-driven: an injected clock, adapter, store, journal, SAFE_MODE controller, alert sink and emergency closer; no internal sleep and no running loop. Phase 24 composes the loop and chooses the step cadence (research Q8), which must be compatible with max_unprotected_ms; that cadence is a Phase 24 number, not decided here.

Reversibility: costly (CONTEXT D-10 rating: changes the order of every entry flow; undoing it needs re-proving on Demo). D-10 is the owner-adopted direction, so no checkpoint re-asks it. O-01 stays open: this plan makes the D-10 flow available but does not enable live orders; LIVE stays blocked until the owner accepts the D055 closure draft (19-DEC-D055-DRAFT.md) and the 11 Demo probes (O-05) are run by the owner.

The intent state machine is not extended (research F6): the STOP_LOSS row uses INTENDED -> SENT -> ACKED/UNKNOWN/REJECTED; the protection state is an in-process enum journaled on every transition, and the exchange (REST) is the truth after a restart. Rebuilding coordinator state after a restart is Phase 20/24 (G4-029); the state names below are stable for Phase 20 (research P8).

Output: src/execution/protection.py, test doubles, coordinator and router-rig tests.
