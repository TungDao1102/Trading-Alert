<objective>
Close what Q5 leaves UNKNOWN (T-C, D-11, D-12; correction 3). Today `resolve_unresolved_intents` finalizes a not-found intent younger than 3 days as REJECTED; for an ENTRY that went UNKNOWN after an ambiguous error that is exactly the conclusion Q5 refused. This plan removes that rule for ENTRY intents and adds an evidence protocol that can close an UNKNOWN entry only on repeated, fresh, journaled Binance evidence.

The plan first asks the owner O-F (the four review resolutions D-11, D-15, D-01a, D-24 pending since CONTEXT) as four independent items; T-C (this plan) is gated by the D-11 item only, T-E (plan 20-15) by the D-15 item only and T-G (plan 20-22) by the D-24 item only. D-01a was built first (plan 20-04, wave 1, strictly fail-closed); the checkpoint shows the owner its executed test evidence and labels anything unexecuted [NOT_TESTED]. The numbers (probe count, interval, grace) stay NOT_CONFIGURED (O-04 / O-G); tests use the TEST_ONLY values of plan 20-01.

Not built here (Phase 24): the caller wiring of recovery into a running process (G4-029) and the notification of the coordinator when an entry is closed RECONCILED_ABSENT (written to the deferred register by plan 20-24).

Executor rules: `codegraph explore "resolve_unresolved_intents _resolve_one _probe IntentProbeAdapter exit_evidence_event"` first; run only this plan's tests; stage explicit paths; commit trailer = the model that did the work; no Binance call (fakes only).
</objective>
