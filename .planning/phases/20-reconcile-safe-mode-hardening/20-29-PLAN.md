## Task 1: CR-C1, an unreadable spill is not an empty spill

- RED: tests that `LocalSpill.scan()` raises on `PermissionError` / `NotADirectoryError` from
  `os.listdir` and returns an empty scan for a missing directory; a startup test where `scan()`
  raises enters SAFE_MODE `RESTORE_INCONSISTENT`, fails `SPILL_READ`, passes `None` to the plan
  builder and does not replay.
- GREEN: `scan()` catches only `FileNotFoundError`; startup skips the replay step of an unreadable
  spill with the same reason. The corrupt-entry handling does not change.
- Files: `src/ops/spill.py`, `src/reconcile/startup.py`, `tests/test_risk_first_spill.py`,
  `tests/test_startup_recovery.py`.

## Task 2: WR-C1 and the gate state file (WR-C2, WR-C9 if small)

- RED: `decode_record` raises `OverflowError` (year 9999 with a negative offset) and
  `RecursionError` (deeply nested JSON); `load()` must set such a file aside, `inspect()` must
  report it corrupt, `status` and `clear` must not crash and `clear` must replace it.
- GREEN: `_parse_time` catches `(ValueError, OverflowError)`; `decode_record` catches
  `RecursionError` with `ValueError`. WR-C9: `_write_atomic` fsyncs the directory after the
  replace (POSIX only, as `LocalSpill` does) and `initialize()` creates the file with
  `O_CREAT | O_EXCL` semantics. WR-C2: `RestRateLimitGate` keeps `_save_failed` as the pending
  flag and the next `check()` / `record()` retries the save.
- Files: `src/ops/rest_gate_state.py`, `src/ops/rest_gate_cli.py` (only if the CLI still crashes),
  `src/adapters/binance_ratelimit_gate.py`, `tests/test_gate_restart.py`,
  `tests/test_rest_gate_cli.py`.

## Task 3: WR-C4, the supervisor does not wait forever on an unknown gate

- RED: a supervisor over a gate with a store in `GATE_STATE_UNKNOWN` (and one never restored)
  starts, retries a bounded number of times, reports one failure and sends nothing; a timed
  429 pause still waits its remaining seconds.
- GREEN: `_await_rest_allowed` counts the checks of a restriction with `until_utc is None` and
  halts when `reconnect_max_attempts` checks were made or `reconnect_max_delay_seconds` of the
  injected clock passed, the same two stops `_bounded_reconnect` uses. The halt reason is the
  gate reason, reported once through `on_failure`; reconcile 20-16 maps any halt to
  `STREAM_TASK_DIED`.
- Files: `src/adapters/binance_userdata_supervisor.py`, `tests/test_userdata_supervisor.py`.
