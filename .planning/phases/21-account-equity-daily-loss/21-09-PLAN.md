<objective>
Persist the UTC day's risk state and its loss components in PostgreSQL (criterion 2 "persisted state", D-07, D-14, F-963) so that a restart inside the day neither resets the day nor moves the base, and a DAILY_STOP latch survives.

Purpose: the pure rules of plan 21-05 need durable rows; the day row is also the row the approval transaction locks (plan 21-12). `system_state_events` is not used (it accepts only str/bool/None values and a fixed key list, 21-RESEARCH Alternatives).
Output: migration 0010, two ORM rows, `PgDayRiskStore`, PostgreSQL tests, the migration-test pins and DATA_MODEL sections.

Reversibility: costly (D-07): a migration and a persisted schema later phases read; the downgrade drops both tables. Not one-way (no other system reads them yet), so no checkpoint.

Pins this plan updates: `tests/test_persistence_migration_pg.py` (REVISION constant and the head assertion near line 470 move to 0010_daily_risk_state; add the 0010 import-guard, revises-0009, upgrade/downgrade and ORM-parity cases in the style of the 0009 block near line 986).
