<objective>
Store the margin each approved-but-unplaced plan will need on its Phase 21 reservation row, and read the claims back, so the placement-time margin check can count the other plans' margin (criterion 3, F-966, D-14).

Purpose: two approvals must not both be counted against the same free margin. The reservation row already serialises risk under the day-row lock (F-407); it now also carries the plan's `required_margin = quantity x entry price / leverage` (computed by `required_initial_margin` of plan 22-04 at plan issue, written by the Phase 24 issuer through `register_request`). Amendment A2 overrides D-14's "sum inside the approval transaction": the exchange reading cannot be taken in the synchronous transaction, so this plan stores the figure and exposes the claims reader; the authoritative sum is taken at placement by the guard (plan 22-14). D-14 is "costly" (a migration and a persisted schema that Phase 21 code reads); the downgrade is real, so it is not one-way.
