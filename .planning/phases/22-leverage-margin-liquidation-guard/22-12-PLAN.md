<objective>
Hold the leverage brackets for a bounded age (D-11), so the liquidation guard never uses a stale or never-read bracket set and never reads the exchange more than it needs to.

Purpose: criterion 2 requires the liquidation check to use exchange brackets, never constants; brackets change per account and over time (Pitfall 11 of the research), so a cache needs an owner-chosen maximum age (the `NOT_CONFIGURED` key of plan 22-02, O-3) and a fail-closed refresh. The cache is an execution-layer object (it awaits the adapter port) built on the pure freshness predicate and the pure `Bracket` type of plan 22-07. The post-fill watch (plan 22-13) and the orchestrator (plan 22-14) both use it.
