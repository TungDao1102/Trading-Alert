<objective>
Only the authorized Telegram user in a private chat can decide (ROADMAP Phase 23 criterion 1, F-508, F-707; CONTEXT D-01, D-02, D-03, D-15, D-17). This is the leading tracer of the phase: one refusal path wired from the environment value through the runtime, the SHADOW coordinator and `on_callback` down to the journal, then every existing caller restored.

Purpose: today the only gate is `authorized_chat_gate` (`chat.id == TELEGRAM_AUTHORIZED_CHAT_ID`); `chat.type` is never read and `from_user` is not checked, so a group in which the bot is a member, or a forwarded keyboard, is not refused by user. The live test of 2026-10-04 also found `actor_id` empty on decided approvals. This plan adds the second, independent gate (D-01 keeps the chat gate: the two fail independently), the required allow-list (D-02, never allow-all), and threads the pressing user's id into the decision (D-03; the PostgreSQL write is plan 23-04).

Orchestrator resolution 7 (recorded here so the owner can override it): no `RejectionReason` member is added. About nine test files pin 21 members and GLOSSARY 9.1 must equal the enum (gate GL-03); the new codes are plain strings with GLOSSARY 9.3 rows (written by plan 23-13), the pattern of `src/execution/pre_placement.py` and `src/approval/binding.py`. This deliberately amends the D-15 wording ("RejectionReason ... the plan updates both"). `DispatchResult.reason_code` widens to `RejectionReason | str | None`.

STATE.md carried item (from plan 16-58): a store or connection failure inside `dispatch_callback` is still reported as `INVALIDATED`; this plan gives it the distinct plain code `APPROVAL_STORE_FAILURE` (the log line by class name stays).
