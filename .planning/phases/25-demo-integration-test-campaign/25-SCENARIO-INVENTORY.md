# Phase 25 scenario inventory (S01-S20)

This is the Wave 0 coverage inventory of `25-RESEARCH.md` (Pattern 5): the one table that maps each
scenario of the pinned catalog (`tests/support/demo_scenarios/catalog.py`, plan 25-08) to its CI twin,
its owner-run Demo test, the existing tests the twin reuses and the evidence labels the owner can expect
on Demo. Written by plan 25-17. `tests/test_phase25_gate.py` parses it and fails if a row is missing, if
a title, path or `leaves_state` value drifts from the catalog, or if the REUSES cell differs (same
entries, same order) from the `REUSES` tuple of the twin file.

How to read it:

- A twin runs in CI on the fake composed process, so every step it records is SYNTHETIC. The Demo test is
  skipped in every agent and CI run; only the owner runs it (D-01). Nothing in this table is a Demo result.
- The label column says what the owner can expect when the scenario runs on Demo (from the 25-RESEARCH
  catalog, refined by what each scenario module records). It is an expectation, not an observation: a
  step the exchange never produced is NOT_OBSERVED, and an injected trigger is never DEMO_OBSERVED.
- `leaves_state` = yes means a failed run can leave a position, a persisted DAILY_STOP or a foreign
  order; the recorded step then names `scripts/demo_clear.py`.
- S20 has no module, twin or Demo test: it is the observation-only set of D-07, carried by rows of
  `docs/operations/DEMO_VS_MAINNET.md` that the owner probes fill in.
