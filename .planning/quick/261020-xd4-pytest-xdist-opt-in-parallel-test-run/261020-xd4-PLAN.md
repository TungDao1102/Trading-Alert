# 261020-xd4: pytest-xdist as an opt-in parallel test run

## Authority
Owner request (2026-10-20): add pytest-xdist so the full test run stops using a single core. Machine: 16 logical cores, about 2.7 GB free RAM, Windows 10; one heavy process at a time, never two pytest runs together.

## Task 1 - dependency
- `uv add --optional dev pytest-xdist` (the dev group is the `dev` extra in `[project.optional-dependencies]`). `git diff uv.lock` may add only pytest-xdist and execnet and change nothing else.
- No `-n` in `addopts`: the default run, the CI gate (`.github/workflows/ci.yml`) and every plan's recorded gate command stay sequential.

## Task 2 - what breaks in parallel
- Static scan of tests for shared mutable state (fixed temp dirs, repo-relative outputs, fixed ports, os.environ without monkeypatch, module caches, git state).
- One `-n 4` run (`-n 3` if free RAM < 3 GB) with memory sampling; collected count equal to the sequential `--collect-only`; skip reasons compared with the 16-64 baseline. Each failure reproduced sequentially and classified (parallel-dependent -> minimal test fix, one commit per root cause; pre-existing -> reported). No skip or xfail added.

## Task 3 - worker count and where the time goes
- `-n 6` only if memory allows, never concurrently with another run. Wall time and peak memory per worker count in `xdist-measurements.txt`; `--durations=30` once in a parallel run.

## Task 4 - documentation
- One line in the AGENTS.md Commands block and the `test.ps1` row in `scripts/dev/README.md`. Preserve line endings (AGENTS.md is CRLF). Then `scripts/verify_decision_alignment.py all`, ruff check, ruff format --check, mypy src, uv lock --check.

## Out of scope
- Recorded gate runs (IMAGE_COMMIT evidence etc.) stay sequential; whether a parallel run counts as equivalent evidence is the owner's decision. No push.
