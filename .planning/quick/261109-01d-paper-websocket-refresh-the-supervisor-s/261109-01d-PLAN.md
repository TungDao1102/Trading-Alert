1. After a rebuild the supervisor's teardown unsubscribes the current stream handles, not the handles of the closed client (today the SDK then warns `No WebSocket connections available for unsubscription.`).
2. The next market-stream silence can be told apart (nothing sent, subscription refused, or one connection dead): frames counted per SDK connection, the answer to every SUBSCRIBE request recorded and logged, SDK warnings carry the stream name when they name one, and one diagnostic snapshot is logged when the watchdog enters the recovery and after each successful rebuild. In-memory counters and structlog events only; nothing is persisted.

Design choice for (1), locked requirement (1) asks for a justification: the ADAPTER resolves an old handle. `PaperWsAdapter` is the only object that creates SDK handles (`subscribe` and `rebuild` both go through `_open_stream`), so it is the only one that knows which old handle belongs to which subscription. Each `_Subscription` keeps the handles it replaced (`retired_handles`), and `unsubscribe(handle)` finds the subscription whose current or retired handle is that object and unsubscribes the CURRENT handle. This changes no signature: `WsAdapterLike`, `PaperSupervisor`, every `WsAdapterLike` double in the tests and the `ObservedWsAdapter` wrapper in `scripts/paper_ws_smoke.py` (which delegates `unsubscribe` to the adapter) stay as they are. The alternative, where the supervisor re-reads handles after a rebuild, needs a new method or a new `rebuild()` return value on `WsAdapterLike`, so every double and the smoke wrapper would have to change.

Design choice for (2b), from reading `binance_common/websocket.py` as installed: `WebSocketStreamBase.subscribe` (line ~1149) and `_resubscribe_global_streams` (line ~979, the SDK's own reconnect) both send SUBSCRIBE through `await self.send_message(json_msg, connection)`. `send_message` (line ~492) stores an asyncio future in `connection.pending_request[id]` and returns it. `receive_loop` (lines ~284-294) pops it when the reply arrives: `set_result(data)` for `{"result": null, "id": ...}`, or `logging.error("Error received from server for request <id>: <error>")` followed by `set_exception(ValueError(data["error"]))`. `subscribe` throws the future away, so nothing reads the answer today. The least invasive hook that is supported and does not alter behaviour: on each client INSTANCE (never the class, never the installed files), the adapter replaces `send_message` with a wrapper. The wrapper awaits the original with the same arguments, attaches `add_done_callback` to the returned future when the payload is a SUBSCRIBE, and returns the same future object. One deliberate side effect: the done callback reads the exception of a refused SUBSCRIBE future, so asyncio's "Future exception was never retrieved" message no longer appears when that future is garbage collected. The refusal is still logged twice: by the SDK's own ERROR line (through the bridge) and by the adapter's ERROR line, which names the streams.
