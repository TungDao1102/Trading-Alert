## Design (fixed by this plan; executors implement it as written)

**Witness object.** Each object sits under `<witness prefix>/<epoch_id>/` of the evidence bucket. Its path relative to that epoch directory is `<slot>-<tick_id>.jsonl`:
- `<slot>` is `YYYYMMDDTHHMMZ` (UTC, minute precision);
- `<tick_id>` is 32 lowercase hex characters;
- the full path matches `(\d{8}T\d{4}Z)-([0-9a-f]{32})\.jsonl`.

The object bytes are exactly the one line the freeze CLI appended, ending in `\n`. The host line's `run_metadata` is `{"schedule": <cron>, "source": "host", "tick_id": <tick_id>}` and carries no `run_id`, `run_attempt` or `event_name`.

**Host verdict.** It is computed for each host tick whose witness time is after the pin and whose witness slot is in the slot grid. The first failing check wins:
1. UNREADABLE: the path does not match; the bytes are absent (`None`, not UTF-8); the byte count is not the listed size; or the bytes are not exactly one JSON object line ending in its only `\n`.
2. NON_CLEAN: the outcome is REGISTRY_DIFF or SKIPPED. Any other outcome that is not clean is UNREADABLE.
3. WRONG_SOURCE: `run_metadata` is not a str-to-str object; `source` is not `host`; any of run_id, run_attempt or event_name is present; or `tick_id` differs from the path's tick id.
4. SCHEDULE_MISMATCH: `schedule` differs from `cron`.
5. WRONG_EPOCH_OR_HASH: `epoch_id` differs from the pin epoch, or either of `pinned_hash` and `current_hash` differs from the pin hash.
6. OUT_OF_SLOT: the path slot differs from the witness slot; `checked_at_utc` is not a UTC-aware time; or `slot <= checked_at_utc <= witnessed_at_utc` does not hold.
7. DUPLICATE: the tick id, or the SHA-256 of the bytes, appears in more than one host tick of the input.
8. LATE_BEYOND_GRACE: `witnessed_at_utc - slot > grace`.
9. Otherwise SATISFIED.

Host ticks witnessed at or before the pin, or whose witness slot is outside the grid, are not judged. That mirrors REV-18 and the as-of bound.

**Slot status.**
- SATISFIED if the GitHub path satisfies the slot or any host result is SATISFIED.
- Otherwise BROKEN if the GitHub path is BROKEN or any host result is NON_CLEAN.
- Otherwise EVIDENCE_GAP with the unchanged GitHub-derived reason and run id.

**Breaks.** A host break is every host tick with `pin < witnessed_at_utc <= window_end_utc` whose bytes are not a readable CLEAN line: an unreadable object, or an outcome that is not clean. It is recorded as `FreezeBreak(at_utc=witnessed_at_utc, outcome=<outcome or "INVALID">, run_id=None, host_path=<path>)` and sorted together with the GitHub breaks.

**Bundle `/2`.** It is `/1` plus two files and a `host_witness` manifest section:
- `host_witness_listing.json`: the raw stdout bytes of the first listing.
- `host_ticks.jsonl`: one canonical JSON row per listed object, sorted by path, `{"path", "size", "sha256", "text"}`. `text` is the object bytes decoded as UTF-8, or null when they are not UTF-8. `sha256` is the hash of the object bytes.
- The `host_witness` section holds `listing_file`, `ticks_file`, `object_count`, a `listing` string naming the rclone command with the placeholder `<witness prefix>/<epoch_id>/`, and a `rule` string citing 16-DEC-HOST-TICK. It never holds a bucket name, a prefix value or a credential.

A bundle without witness input stays `/1`. An older loader refuses `/2` by schema, so it fails closed.
