## Design choices (decided here; cite them in the code comments and D113)

- DC-1 Count and pacing: reuse `_CONFIRM_REREADS` (3) and `_CONFIRM_REREAD_DELAY_SECONDS` (0.5 s) and the
  same `await asyncio.sleep(...)`; at most 4 reads and 1.5 s added to one protection step, only on the
  non-ACTIVE path, once per plan. No new constant, no limit key, no number chosen (D-12).
- DC-2 A dedicated private helper `_read_stop_by_rest(*, adapter, client_algo_id) -> str | None` placed
  right after `_confirm_leg_by_rest`, with the same loop shape and the same terminal predicate, returning
  None when the stop reads ACTIVE and otherwise today's detail text. Not a call of `_confirm_leg_by_rest`
  itself, because that would change the four pinned and journaled stop details and its `found is None`
  test would reread a non-boolean `found` that today is held at once. `_confirm_leg_by_rest` stays
  byte-identical.
- DC-3 Reread classes: found False -> reread; found True with class UNKNOWN (TRIGGERING, TRIGGERED,
  FINISHED, CANCELED, None, unseen) -> reread, exactly as the TP helper does; class TERMINAL_FAILED ->
  hold at once; exception or found neither True nor False on ANY read -> hold at once; the detail after
  the last read is the one of that read.
- DC-4 Alert reason = `reason_code`. The free detail is not shown in the alert: it is free text (role,
  exception class, status repr); an enum form would need a new vocabulary and a second alert field
  (OperationalAlert has one reason, src/ops/alerts.py:203-212). It stays in the journal note and the
  RUNBOOK says how to read it.
- DC-5 Golden: the generator case reason becomes ENTRY_WITHOUT_PROTECTIVE (the code every refusal of
  attach carries, i.e. the 2026-11-15 case), regenerated by the script; wording unchanged.
- DC-6 Not in scope (residual for the owner): attach does not use the listing cross-check of plan 20-27.
  If Demo's by-id lag outlasts the 4 reads, the hold still happens (fail closed), now with a readable code.
