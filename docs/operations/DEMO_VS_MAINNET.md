# Demo versus mainnet: what Binance Demo has shown, what was injected, what only mainnet can show

Status: Phase 25 plan 25-06 (D-07, D-12, ROADMAP criterion 4). Written by the assistant from evidence that already exists in the repository; owner review pending. Nothing in this document was observed on mainnet, and no row is labelled as mainnet-observed. Binance Demo Trading is not mainnet: a result recorded here says what Demo did on the date of the evidence, not what the live exchange will do.

Readers: Phase 26 (CANARY) reads this table to decide what the first real-money checks must prove. A row that says DEMO_OBSERVED is a fact about Demo only. A row that says NOT_OBSERVED is a gap the canary or a later Demo session has to close, or a gap that stays open on purpose.

Document owner rule (25-RESEARCH Pitfall 9): an injected fault is never recorded as exchange behaviour, and a missing observation is never recorded as a result. A row without evidence is NOT_OBSERVED, whatever the code assumes.

## Labels

| Label | Meaning | What the Source column must hold |
|---|---|---|
| DEMO_OBSERVED | Seen on Binance Demo, from a recorded run. The trigger was a real request or a real network condition, and the answer came from the exchange. | An evidence file path with the case or step id, and a Demo order id or client id where one exists. |
| DEMO_FAULT_INJECTED | The trigger was injected at the test edge (a forced disconnect, a raised error, a skewed clock, a stale feed). The reaction of the project's code ran against Demo. This is never exchange behaviour. | The evidence file or test that shows the reaction, and the injection used. |
| DOCS | Stated on an official Binance documentation page and not observed on Demo. | The documentation URL, and the repository record of when it was read. |
| NOT_OBSERVED | No evidence exists. The row states the reason. | The reason, and where an observation could be made. |

Nothing is labelled mainnet-observed: the project has not sent a request to a mainnet account.

## How a row changes

1. Only evidence changes a label: a recorded file, a case or step id, and the order or client id.
2. The NOT_OBSERVED rows DVM-28, DVM-29 and DVM-30 do not move on any Demo result, because a ban is never provoked. They move only if a real ban occurs by accident and its body is recorded.
3. An injected trigger is DEMO_FAULT_INJECTED even when the reaction ran against Demo. It never turns into DEMO_OBSERVED.
4. This document changes no decision, no parameter and no flag. Any change of `LIVE_NET_PNL_SEMANTICS_VERIFIED`, `AVAILABLE_BALANCE_NETS_RESTING_ORDERS_VERIFIED` or the TP1 gate needs its own DECISIONS row.
